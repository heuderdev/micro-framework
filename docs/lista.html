Listagens

Tabelas e listas com paginação, ordenação, filtros, busca com espera, URL compartilhável, seleção em lote, "carregar mais", rolagem infinita e atualização automática depois de um cadastro. Requer alpine-form-lista.

Instalação

<script src="/js/alpine-form/alpine-form.min.js"></script>
<script src="/js/alpine-form/alpine-form-lista.min.js"></script>    <!-- depois do núcleo -->
<script defer src="/js/alpine.min.js"></script>
ESM
import lista from 'alpine-form/lista'
AlpineForm.use(lista)

O módulo não gera as linhas: elas são o seu HTML (x-for sobre $lista.itens). Ele cuida de buscar os dados, dos parâmetros, dos estados e da navegação. Exemplo executável: examples/lista.php.

Listagem mínima

<section id="clientes" x-data x-lista data-lista-url="/api/clientes">
    <table>
        <thead><tr><th>Nome</th><th>E-mail</th></tr></thead>
        <tbody>
            <template x-for="item in $lista.itens" :key="item.id">
                <tr><td x-text="item.nome"></td><td x-text="item.email"></td></tr>
            </template>
        </tbody>
    </table>
    <p data-lista-status></p>
    <nav data-lista-paginacao></nav>
</section>
  1. Ao abrir, faz GET /api/clientes?page=1&per_page=20.
  2. Preenche $lista.itens; o Alpine desenha as linhas.
  3. [data-lista-status] mostra "Carregando…", "Mostrando 1–20 de 137", "Nenhum resultado encontrado." ou o erro.
  4. [data-lista-paginacao] vazio recebe a navegação: Anterior, 1 … 4 5 [6] 7 8 … 20, Próxima (botões com aria-current).

O que o servidor responde

Parâmetros enviados (nomes do Laravel, configuráveis): page, per_page, sort, direction (asc/desc) e cada filtro pelo name. Formatos reconhecidos automaticamente:

FormatoExemplo
Laravel API Resource{ "data": [...], "meta": { "current_page": 1, "last_page": 7, "per_page": 20, "total": 137 } }
Laravel paginate(){ "data": [...], "current_page": 1, "last_page": 7, "per_page": 20, "total": 137 }
Laravel simplePaginate(){ "data": [...], "current_page": 1, "per_page": 20, "next_page_url": "…" } (sem total)
Contrato AlpineForm / Joomla JsonResponse{ "success": true, "data": { "itens": [...], "total": 137, "pagina": 1, "por_pagina": 20 } }
Itens + total{ "items": [...], "total": 137 } (também itens, results, registros)
Lista simples[ ... ] (sem total; "próxima" existe se vier a página cheia)
Laravel
public function index(Request $request)
{
    $ordenaveis = ['nome', 'criado_em', 'saldo'];                   // nunca ordene por coluna vinda direto da URL
    $ordem = in_array($request->sort, $ordenaveis, true) ? $request->sort : 'nome';
    $direcao = $request->direction === 'desc' ? 'desc' : 'asc';

    return ClienteResource::collection(
        Cliente::query()
            ->when($request->busca, fn ($q, $b) => $q->where('nome', 'like', "%{$b}%"))
            ->when($request->uf, fn ($q, $uf) => $q->where('uf', $uf))
            ->orderBy($ordem, $direcao)
            ->paginate(min((int) $request->per_page ?: 20, 100))
    );
}

Sempre valide no servidor a coluna de ordenação (lista branca), o tamanho máximo da página e cada filtro. A listagem é só um GET com parâmetros: qualquer pessoa pode alterá-los.

Ordenação

<section x-data x-lista data-lista-url="/api/clientes" data-lista-ordem="nome" data-lista-direcao="asc">
    <table>
        <thead>
            <tr>
                <th><button type="button" data-lista-ordenar="nome">Nome</button></th>
                <th><button type="button" data-lista-ordenar="criado_em">Cadastro</button></th>
            </tr>
        </thead>
        <tbody>
            <template x-for="item in $lista.itens" :key="item.id">
                <tr><td x-text="item.nome"></td><td x-text="item.criado_em"></td></tr>
            </template>
        </tbody>
    </table>
</section>
  • Clicar alterna crescente/decrescente e volta para a página 1.
  • O <th> recebe aria-sort (ascending/descending/none) e o botão, data-lista-direcao-atual — use para a seta no CSS: [data-lista-direcao-atual="asc"]::after { content: " ▲" }.
  • Pelo código: $lista.ordenar('nome'), $lista.ordenar('nome', 'desc'), $lista.direcaoDe('nome').

Filtros e busca

<section x-data x-lista data-lista-url="/api/clientes" data-lista-debounce="300ms">
    <form data-lista-filtros role="search">
        <input name="busca" type="search" placeholder="Buscar" data-lista-minimo="2">
        <select name="uf"><option value="">Todas</option><option>SP</option><option>RJ</option></select>
        <label><input type="checkbox" name="status[]" value="ativo"> Ativo</label>
        <label><input type="checkbox" name="status[]" value="inativo"> Inativo</label>
        <input name="de" type="date"> <input name="ate" type="date">
        <button type="button" data-lista-limpar>Limpar</button>
    </form>
    <template x-for="item in $lista.itens" :key="item.id"><p x-text="item.nome"></p></template>
</section>
ControleQuando busca
Texto (input, search, textarea)Depois que a digitação para (data-lista-debounce, padrão 300 ms). Com data-lista-minimo="2", só busca com 2+ caracteres (ou vazio). A requisição anterior é cancelada; resposta antiga nunca sobrescreve a nova.
Select, checkbox, radio, datasNa hora (evento change).
Formulário com data-lista-aplicar-ao-enviarSó ao enviar (botão "Filtrar" ou Enter).
  • Filtros podem estar num <form data-lista-filtros> (todos os campos com name) ou em campos soltos com data-lista-filtro.
  • Mudar filtro volta para a página 1. Valores vazios não são enviados. Grupos (status[]) e select múltiplo enviam todos os marcados.
  • Com o filtro dentro de um x-form e máscara (CPF, moeda, data), vai a representação de envio (ex.: CPF sem pontos).
  • data-lista-ignorar exclui um campo dos filtros. data-lista-limpar volta aos valores iniciais do HTML.
  • Pelo código: $lista.filtrar('uf', 'SP'), $lista.definirFiltros({ uf: 'SP', busca: '' }) (null remove), $lista.limparFiltros(), $lista.filtros.

data-lista-anterior/data-lista-proxima se desabilitam sozinhos. Pelo código: $lista.irPara(3), $lista.proxima(), $lista.anterior(), $lista.definirPorPagina(50). Se um filtro reduzir os resultados e a página atual deixar de existir, a lista volta para a última página válida.

URL compartilhável (data-lista-url-sincronizar)

<section x-data x-lista data-lista-url="/api/clientes" data-lista-url-sincronizar> ... </section>
  • Página, tamanho, ordenação e filtros vão para a URL do navegador (/clientes?page=3&sort=nome&busca=ana). Recarregar ou compartilhar o link reabre a mesma visão, com os campos de filtro preenchidos.
  • Trocar de página ou ordenação cria entrada no histórico (Voltar/Avançar funcionam); digitar num filtro só substitui a URL atual.
  • Duas listas sincronizadas na mesma página: data-lista-url-prefixo="pedidos_" em uma delas para não colidir os parâmetros.

Seleção em lote

<section x-data x-lista data-lista-url="/api/clientes">
    <input type="checkbox" data-lista-selecionar-todos aria-label="Selecionar todos desta página">
    <template x-for="item in $lista.itens" :key="item.id">
        <label><input type="checkbox" :data-lista-selecionar="item.id"> <span x-text="item.nome"></span></label>
    </template>
    <p x-show="$lista.quantidadeSelecionada > 0">
        <span x-text="$lista.quantidadeSelecionada"></span> selecionado(s)
        <button type="button" @click="$lista.limparSelecao()">Limpar</button>
    </p>
</section>
  • A seleção é mantida ao trocar de página; o checkbox de "todos" vale para a página atual e fica indeterminado quando parte está marcada.
  • $lista.selecionados (chaves como texto), $lista.itensSelecionados(), $lista.alternar(id), $lista.alternarTodos(). A chave padrão é id (data-lista-chave="codigo" para outra). Evento lista:selecao.
Ação em lote com x-form
<section id="clientes" x-data x-lista data-lista-url="/api/clientes">
    <form x-data x-form action="/api/clientes/arquivar" method="post" data-form-lista="clientes" novalidate>
        <template x-for="id in $lista.selecionados" :key="id"><input type="hidden" name="ids[]" :value="id"></template>
        <button type="submit" x-bind:disabled="$lista.quantidadeSelecionada === 0">Arquivar selecionados</button>
    </form>
    <!-- tabela com data-lista-selecionar ... -->
</section>

O formulário fica dentro do x-lista para enxergar $lista (fora dele, use data-lista-para="clientes" num elemento acima do form); depois do sucesso, data-form-lista recarrega a lista.

Carregar mais e rolagem infinita

<section x-data x-lista data-lista-url="/api/produtos" data-lista-modo="acumular" data-lista-por-pagina="12">
    <template x-for="item in $lista.itens" :key="item.id"><article x-text="item.nome"></article></template>
    <p data-lista-status></p>
    <button type="button" data-lista-mais>Carregar mais</button>   <!-- some quando não há mais -->
    <div data-lista-sentinela aria-hidden="true"></div>           <!-- opcional: carrega sozinho ao aparecer na tela -->
</section>

Em acumular, cada página nova é acrescentada. O sentinela usa IntersectionObserver e continua carregando até sair da área visível (telas altas são preenchidas). Pelo código: $lista.maisItens().

Cadastro atualiza a lista (data-form-lista)

Depois de salvar um formulário com sucesso, as listas indicadas buscam os dados de novo na API — o registro novo aparece sem recarregar a página.

<form id="novo-cliente" x-data x-form action="/api/clientes" method="post"
      data-form-lista="clientes resumo" data-form-reset-on-success novalidate>
    <input name="nome" data-form-v="required">
    <button type="submit">Cadastrar</button>
</form>

<section id="clientes" x-data x-lista data-lista-url="/api/clientes" data-lista-destacar>
    <template x-for="item in $lista.itens" :key="item.id">
        <p :class="{ 'novo': $lista.destaque === String(item.id) }" x-text="item.nome"></p>
    </template>
</section>

<section id="totais" x-data x-lista data-lista-url="/api/clientes/por-uf" data-lista-grupo="resumo"> ... </section>
<section id="grafico" x-data x-lista data-lista-url="/api/clientes/por-mes" data-lista-grupo="resumo"> ... </section>
AtributoOndeEfeito
data-form-lista="a b"<form>Depois do sucesso, atualiza as listas cujo id ou data-lista-grupo seja a ou b. Erro no envio não atualiza nada.
data-lista-grupo="resumo dashboard"listaNomes de grupo: várias listas atualizam juntas com um só alvo.
data-lista-ao-atualizarlistarecarregar (padrão: mantém página, filtros e ordem) ou inicio (volta à página 1 — útil quando o novo aparece no topo). No modo acumular, sempre recomeça.
data-lista-destacar / ="6s"listaSe a resposta do formulário trouxer data.id, deixa essa chave em $lista.destaque por 4 s (ou o tempo indicado).
  • Alvo que não corresponde a nenhuma lista na página gera aviso no console (provável erro de digitação).
  • Também funciona com processamento posterior (202): a atualização acontece quando o job termina com sucesso.
  • Sem formulário: AlpineForm.lista.atualizar('clientes') (devolve quantas listas atualizou) ou document.dispatchEvent(new CustomEvent('lista:atualizar', { detail: { alvos: 'clientes' } })). A lista dispara lista:atualizada.
Excluir uma linha e atualizar
<template x-for="item in $lista.itens" :key="item.id">
    <form x-data x-form :action="'/api/clientes/' + item.id + '/excluir'" method="post" data-form-lista="clientes resumo" novalidate
          @form:before-submit="confirm('Excluir?') || $event.preventDefault()">
        <span x-text="item.nome"></span>
        <button type="submit">Excluir</button>
    </form>
</template>

Estados: carregando, vazio, erro

<div x-show="$lista.carregando && !$lista.carregado">Carregando…</div>
<div x-show="$lista.vazio">Nenhum cliente encontrado. <button type="button" data-lista-limpar>Limpar filtros</button></div>
<div x-show="$lista.erro" role="alert">
    <span x-text="$lista.erro?.message"></span>
    <button type="button" data-lista-recarregar>Tentar de novo</button>
</div>
<table :class="{ 'carregando': $lista.carregando }"> ... </table>
  • Em erro (rede, 401, 403, 500, HTML, formato inesperado), a lista anterior continua na tela e $lista.erro traz { kind, status, message }; evento lista:erro.
  • O contêiner recebe aria-busy="true" enquanto carrega.
  • data-lista-carregar="manual" não busca ao abrir (chame $lista.recarregar()).
  • data-lista-atualizar="30s" recarrega periodicamente (pausa com a aba oculta) — painéis e filas de atendimento.

Exportar com os filtros atuais

<a x-bind:href="$lista.urlCom('/clientes/exportar.csv')">Exportar CSV</a>

urlCom(base) devolve a URL com os mesmos filtros e ordenação, sem paginação. $lista.parametros e $lista.queryString dão acesso aos parâmetros atuais.

// API que responde { registros: [...], qtd: 137, pag: 2, paginas: 7 }
