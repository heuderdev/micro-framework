Envio

Para onde e como os dados vão: método, formato (multipart, urlencoded, JSON), nomes com colchetes, botão clicado, cabeçalhos, CSRF, envio duplicado, idempotência, redirecionamento e envio pelo código.

Destino e método

Vale o que o HTML diz: action e method do form, ou formaction/formmethod do botão clicado. Para sobrescrever sem mexer no action (útil quando o form também precisa funcionar sem JavaScript):

<form x-data x-form action="/cadastro" method="post"
      data-form-endpoint="/api/cadastro" data-form-method="put" novalidate>

Métodos aceitos: get, post, put, patch, delete. Em get, os dados vão na URL.

Ação dinâmica com Alpine
<form x-data="{ id: 7 }" x-form :action="`/api/clientes/${id}`" method="post" novalidate>

Formato do corpo

data-form-encodingCorpoQuando usar
multipart (padrão)FormDataSempre funciona, inclusive com arquivos. No PHP: $_POST e $_FILES.
urlencodeda=1&b=2Formulários sem arquivo, backends antigos.
json{"a":"1"}APIs JSON. Arquivos não vão (ver abaixo).

O enctype do form também é respeitado (multipart/form-data, application/x-www-form-urlencoded), a menos que data-form-encoding esteja presente.

Lendo JSON no PHP
$dados = json_decode(file_get_contents('php://input'), true) ?? [];

JSON e nomes com colchetes

<form x-data x-form action="/api/pedido" method="post" data-form-encoding="json" novalidate>
    <input name="cliente[nome]" value="Ana">
    <input name="cliente[email]" value="ana@ex.com">
    <input name="itens[0][produto]" value="Caneta">
    <input name="itens[0][qtd]" value="2">
    <input type="checkbox" name="tags[]" value="urgente" checked>
    <input type="checkbox" name="tags[]" value="presente" checked>
</form>
Corpo enviado
{
  "cliente": { "nome": "Ana", "email": "ana@ex.com" },
  "itens": [ { "produto": "Caneta", "qtd": "2" } ],
  "tags": ["urgente", "presente"]
}
data-form-nestingusuario.emaila[b]
brackets (padrão)chave literal "usuario.email"{"a":{"b":…}}
dots{"usuario":{"email":…}}{"a":{"b":…}}
flatchave literalchave literal "a[b]"; nomes repetidos viram lista

Valores vão como texto (o JSON não converte "2" em número). Nomes como __proto__ ou constructor são recusados por segurança. Arquivo com JSON é erro; para enviar só os dados do arquivo (nome, tamanho, tipo) use data-form-json-files="metadata", e para enviar o conteúdo, multipart ou upload em partes.

O que é enviado

A montagem segue as regras do HTML, com três diferenças úteis:

  • Igual ao HTML: ordem da página; nomes repetidos viram entradas repetidas; desabilitados, sem name e checkbox/radio desmarcados ficam de fora; o botão clicado entra com name/value; controles com form="id" fora do form entram.
  • Máscaras e normalizadores: vai a representação escolhida em data-form-submit-value.
  • Arquivos: vai a lista interna (arquivos removidos na tela não são enviados).
  • Checkbox com data-form-unchecked-value: desmarcado, envia esse valor.
Ver o que seria enviado
<pre x-text="JSON.stringify($form.getValues({ format: 'entries' }), null, 2)"></pre>

Cabeçalhos

Enviados sempre: Accept (JSON preferido) e X-Requested-With: XMLHttpRequest. Com meta tag de CSRF e URL da mesma origem: X-CSRF-TOKEN. Para acrescentar:

<form x-data x-form action="/api/x" method="post" data-form-header.X-Tenant="acme" data-form-header.Accept-Language="pt-BR" novalidate>
Para todos os formulários
AlpineForm.configure({ headers: { Authorization: 'Bearer ' + token } })
Último ajuste antes de enviar
AlpineForm.configure({
    hooks: {
        beforeRequest(request) {
            request.headers['X-Hora-Local'] = new Date().toISOString()
        },
    },
})

Cookies em outra origem

<form x-data x-form action="https://api.outrodominio.com/contato" method="post" data-form-credentials="include" novalidate>

Padrão same-origin. Com include, cookies vão para outra origem (o servidor precisa responder CORS com Access-Control-Allow-Credentials). O cabeçalho CSRF da meta tag nunca é enviado para outra origem.

Clique duplo e envio duplicado

Enquanto um envio está em andamento, novos envios (clique duplo, Enter repetido, $form.submit()) recebem a mesma operação — só uma requisição sai. Desabilitar o botão é opcional, mas deixa claro para o usuário:

<button type="submit" :disabled="$form.submitting" x-text="$form.submitting ? 'Enviando…' : 'Enviar'"></button>

Idempotência (evitar pedido em dobro)

Se a conexão cai depois do envio, não dá para saber se o servidor gravou. A biblioteca nunca reenvia sozinha; mostra "A conexão caiu depois do envio. Não é possível confirmar se a operação foi concluída; verifique antes de enviar novamente.". Com data-form-idempotency, cada envio leva o cabeçalho Idempotency-Key, e se a pessoa tentar de novo com os mesmos dados depois de um resultado desconhecido (ou erro 5xx/429), a mesma chave é reaproveitada — o servidor pode devolver a resposta já gravada em vez de criar outro pedido.

<form x-data x-form action="/api/pedidos" method="post" data-form-idempotency novalidate>

Implementação no servidor: Backend › Idempotência.

Tempo limite

<form x-data x-form action="/api/x" method="post" data-form-timeout="30s" novalidate>

Padrão: sem limite. Ver Progresso › tempo limite para o que acontece quando estoura.

Depois do sucesso

Limpar o formulário
<form x-data x-form action="/api/contato" method="post" data-form-reset-on-success novalidate>
Ir para a URL que o servidor indicar
<form x-data x-form action="/api/login" method="post" data-form-redirect="response" novalidate>
<!-- resposta: { "success": true, "redirect": "/painel" } -->

O redirecionamento só acontece para http(s) da mesma origem, ou de origens listadas: data-form-redirect-origins="https://pagamento.exemplo.com". Outras URLs são ignoradas (e registradas no console).

Fazer algo seu
<form x-data x-form action="/api/clientes" method="post"
      @form:success="window.location.href = '/clientes/' + $event.detail.result.data.id" novalidate>

Enviar pelo código

<button type="button" @click="$form.submit().then(r => r.ok && alert('Salvo!'))">Salvar</button>

submit() devolve { ok: true, result } ou { ok: false, reason }, com reason = invalid, canceled, prevented ou o tipo do erro. Nunca rejeita por erro de validação ou do servidor.

Impedir ou condicionar o envio

<form x-data x-form action="/api/excluir" method="post"
      @form:before-submit="if (!confirm('Excluir mesmo?')) $event.preventDefault()" novalidate>
Com hook (aceita async)
AlpineForm.configure({
    hooks: {
        async beforeSubmit(state, { submitter }) {
            return await meuModal.confirmar('Enviar?')   // false cancela
        },
    },
})

Envio tradicional (sem AJAX)

Para só validar no navegador e deixar o envio normal (com recarregamento da página):

<form x-data x-form action="/salvar" method="post" data-form-transport="native" novalidate>
