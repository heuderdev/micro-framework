Condicionais e dependências

Campos que dependem de outros (confirmação de senha, intervalo de datas, "obrigatório se") e campos que aparecem e somem com x-show, x-if ou disabled.

Dependências entre campos

Toda regra que cita outro campo (same, different, required_if, required_unless, required_with, required_without, greater_than… e datas com nome de campo) cria uma dependência: quando o campo citado muda, o dependente é revalidado automaticamente — se ele já foi validado, tocado ou se o envio já foi tentado.

Confirmação de senha
<input name="senha" type="password" data-form-v="required|min:8">
<input name="senha_confirmacao" type="password" data-form-v="required|same:senha"
       data-form-msg.same="As senhas não conferem.">

Se a pessoa preenche a confirmação e depois altera a senha, o erro "As senhas não conferem." aparece (ou some) na confirmação sem que ela precise tocar nela.

Intervalo de datas
<input name="inicio" type="date" data-form-v="required|after_or_equal:today">
<input name="fim" type="date" data-form-v="required|after_or_equal:inicio"
       data-form-msg.after_or_equal="O fim não pode ser antes do início.">
Faixa de valores
<input name="minimo" data-form-mask="currency" data-form-v="required">
<input name="maximo" data-form-mask="currency" data-form-v="required|greater_than:minimo">

Referência a um campo inexistente é erro de configuração ("O campo "fim" referencia "inicioo", que não existe neste formulário."). Ciclos (A depende de B e B de A) são permitidos: a revalidação é de um nível e não entra em laço.

Obrigatório só em certas condições

Pessoa física ou jurídica
<label><input type="radio" name="tipo" value="pf" data-form-v="required"> Física</label>
<label><input type="radio" name="tipo" value="pj"> Jurídica</label>

<input name="cpf"  data-form-mask="cpf"  data-form-v="required_if:tipo,pf|cpf">
<input name="cnpj" data-form-mask="cnpj" data-form-v="required_if:tipo,pj|cnpj">
"Outro" com campo de texto
<select name="origem" data-form-v="required">
    <option value="">Selecione</option>
    <option value="busca">Busca</option>
    <option value="indicacao">Indicação</option>
    <option value="outro">Outro</option>
</select>
<input name="origem_outro" data-form-v="required_if:origem,outro|max:80">
Pelo menos um contato
<input name="email" type="email" data-form-v="required_without:telefone|email"
       data-form-msg.required_without="Informe e-mail ou telefone.">
<input name="telefone" data-form-mask="telefone_br" data-form-v="required_without:email|telefone"
       data-form-msg.required_without="Informe e-mail ou telefone.">

Mostrar e esconder campos

Campos escondidos não são dispensados automaticamente — você escolhe a política. Três formas:

FormaValida quando escondido?Envia quando escondido?Quando usar
x-show + data-form-hidden="skip"NãoSim (valor atual)Bloco que só aparece em certas condições, mas o servidor ignora os valores.
:disabledNãoNãoO servidor não deve receber o campo.
x-ifNão (o campo deixa de existir)NãoO campo não faz sentido; ao voltar, começa limpo.
x-show + data-form-hidden="skip"
<form x-data="{ entrega: 'retirada' }" x-form action="/pedido" method="post" novalidate>
    <label><input type="radio" name="entrega" value="retirada" x-model="entrega"> Retirar</label>
    <label><input type="radio" name="entrega" value="casa" x-model="entrega"> Entregar</label>

    <div x-show="entrega === 'casa'" data-form-hidden="skip">
        <input name="cep" data-form-mask="cep" data-form-v="required|cep">
        <input name="numero" data-form-v="required|digits">
    </div>
    <button type="submit">Enviar</button>
</form>
:disabled
<input name="complemento" :disabled="entrega !== 'casa'" data-form-v="max:60">
x-if
<label><input type="checkbox" x-model="temCupom"> Tenho cupom</label>
<template x-if="temCupom">
    <input name="cupom" data-form-v="required|alphanumeric|length:8">
</template>

data-form-hidden pode ficar no campo, num elemento acima dele ou no form (vale para todos). Com o padrão validate, campos escondidos continuam sendo validados — e o erro pode aparecer num campo que a pessoa não vê.

Com x-show sem skip, um campo obrigatório escondido bloqueia o envio. Se o erro está num lugar invisível, o foco não consegue chegar nele. Escolha uma das três formas acima.

Abas, accordions e modais

Campos dentro de uma aba fechada continuam visíveis para o AlpineForm (não estão desabilitados). No envio inválido, o hook reveal permite abrir a aba antes do foco:

<form x-data="{ aba: 'dados' }" x-form="{ hooks: { reveal: el => { aba = el.closest('[data-aba]').dataset.aba } } }"
      action="/salvar" method="post" novalidate>
    <button type="button" @click="aba = 'dados'">Dados</button>
    <button type="button" @click="aba = 'endereco'">Endereço</button>

    <div data-aba="dados" x-show="aba === 'dados'">
        <input name="nome" data-form-v="required">
    </div>
    <div data-aba="endereco" x-show="aba === 'endereco'">
        <input name="cep" data-form-mask="cep" data-form-v="required|cep">
    </div>
    <button type="submit">Salvar</button>
</form>

Alternativa sem hook: escute o evento form:reveal (disparado no campo, sobe até o form): @form:reveal="aba = $event.target.closest('[data-aba]').dataset.aba".
