Regras

Todas as regras de data-form-v, com parâmetros, comportamento e exemplo. Mensagens padrão entre aspas.

Regras de presença rodam sempre. As demais não rodam com o campo vazio: um campo opcional vazio é válido. Vazio é: nada digitado (ou só espaços), nenhuma opção marcada, nenhum arquivo. 0, "0" e false não são vazios.

Presença

required

Obrigatório. Em grupos e selects múltiplos, exige ao menos um item; em checkbox individual, marcado; em arquivo, ao menos um (contando os existentes na edição).

Mensagens: "O campo :field é obrigatório." · radio/select: "Selecione uma opção em :field." · múltipla: "Selecione ao menos uma opção em :field." · checkbox: "Marque :field para continuar." · arquivo: "Selecione um arquivo em :field."

<input name="nome" data-form-v="required">

optional · nullable

Marcadores sem efeito na validação: documentam que o campo pode ficar vazio. Combinar com required é erro de configuração.

accepted

Checkbox marcado (termos de uso). Em outros campos, aceita 1, on, yes, sim, true.

Mensagem: "Você precisa aceitar :field."

<label><input type="checkbox" name="termos" value="1" data-form-v="accepted" data-form-label="os termos de uso"> Aceito os termos</label>

required_if:campo,valor1,valor2…

Obrigatório quando o outro campo tem um dos valores. Para "quando o outro estiver vazio", use o valor vazio: required_if:tipo,. Revalida automaticamente quando o outro campo muda.

<select name="tipo"><option value="pf">Física</option><option value="pj">Jurídica</option></select>
<input name="cnpj" data-form-v="required_if:tipo,pj|cnpj">

required_unless:campo,valor1,valor2…

Obrigatório, exceto quando o outro campo tem um dos valores.

<input name="cpf" data-form-v="required_unless:estrangeiro,1|cpf">
<label><input type="checkbox" name="estrangeiro" value="1"> Sou estrangeiro</label>

required_with:campo1,campo2…

Obrigatório quando qualquer um dos outros está preenchido. "O campo :field é obrigatório quando :other for informado."

<input name="telefone" data-form-mask="telefone_br" data-form-v="telefone">
<input name="ramal" data-form-v="digits">
<input name="contato_nome" data-form-v="required_with:telefone,ramal">

required_without:campo1,campo2…

Obrigatório quando algum dos outros está vazio. Clássico "informe e-mail ou telefone":

<input name="email" type="email" data-form-v="required_without:telefone|email">
<input name="telefone" data-form-mask="telefone_br" data-form-v="required_without:email|telefone">

Texto

min:n · max:n · between:a,b

Mudam de sentido conforme o campo: texto → quantidade de caracteres; número (type="number", máscara numérica ou regra numeric/integer/decimal no campo) → valor; lista (checkboxes, select múltiplo) → quantidade de itens. Em arquivo é erro (use files_max/file_max).

Mensagens: "Digite pelo menos :min caracteres." · "O valor mínimo de :field é :min." · "Selecione pelo menos :min opções."

<input name="nome" data-form-v="required|min:3|max:120">
<input name="idade" type="number" data-form-v="required|min:18|max:120">
<input type="checkbox" name="cores[]" value="azul" data-form-v="min:2|max:3"> ...
<input name="parcelas" data-form-v="integer|between:1,12">

length:n · min_length:n · max_length:n

length: exatamente n caracteres (ou itens, em listas). min_length/max_length: sempre caracteres, mesmo em campo numérico. Caracteres contados por code point (acentos e a maioria dos emojis contam 1).

<input name="uf" data-form-v="required|length:2">
<input name="codigo" type="number" data-form-v="min_length:4|max_length:6">

email · email:loose

E-mail com domínio contendo ponto (usuario@empresa.com). loose também aceita domínio sem ponto (admin@localhost). Até 254 caracteres.

<input name="email" type="email" data-form-v="required|email">

url · url:esquema1,esquema2

Endereço absoluto. Padrão: http e https. Liste outros esquemas se quiser aceitá-los.

<input name="site" data-form-v="url">
<input name="repositorio" data-form-v="url:https,ssh">

pattern + data-form-pattern

Expressão regular no atributo data-form-pattern (até 500 caracteres). Flags permitidas em data-form-pattern-flags: i, m, s, u. Use ^…$ para exigir o texto inteiro. Entradas acima de 2000 caracteres falham.

Mensagem: "O formato de :field é inválido."

<input name="placa" data-form-v="required|pattern" data-form-pattern="^[A-Z]{3}-?[0-9][A-Z0-9][0-9]{2}$"
       data-form-pattern-flags="i" data-form-msg.pattern="Placa inválida.">

alpha · alphanumeric · :spaces

Só letras (inclusive acentuadas) / letras e números. Com :spaces, também espaços, hífen e apóstrofo (nomes como "Maria D'Ávila").

<input name="nome" data-form-v="required|alpha:spaces">
<input name="usuario" data-form-v="required|alphanumeric">

digits · digits:n

Só dígitos 0–9 (sem sinal, ponto ou espaço). Com n, exatamente n dígitos: ":field deve conter exatamente :length dígitos."

<input name="numero" data-form-v="required|digits">
<input name="pin" data-form-v="required|digits:4">

in:a,b,c · not_in:a,b,c

Valor deve estar (ou não estar) na lista. Em listas (checkboxes), cada item é conferido.

<input name="tamanho" data-form-v="required|in:P,M,G,GG">
<input name="usuario" data-form-v="required|not_in:admin,root,sistema">

starts_with:… · ends_with:… · contains:…

Começa com algum / termina com algum / contém todos os valores.

<input name="email_corp" data-form-v="email|ends_with:@empresa.com.br,@empresa.com">
<input name="codigo" data-form-v="starts_with:PED-,ORC-">

Números

Regras numéricas comparam o texto como decimal exato (sem erro de arredondamento) e aceitam ponto como separador decimal: 1234.56. Para o usuário digitar 1.234,56, use uma máscara numérica (que valida o valor canônico) ou data-form-normalize="decimal".

numeric · integer

Número (com sinal e decimais opcionais) / inteiro.

<input name="peso" data-form-v="required|numeric">
<input name="quantidade" data-form-v="required|integer|min:1">

decimal:max · decimal:min,max

Quantidade de casas decimais: até max, ou entre min e max.

<input name="preco" data-form-v="required|decimal:2">
<input name="taxa" data-form-v="decimal:2,4">

min_value:x · max_value:x · positive · negative · multiple_of:x

Comparação de valor, independentemente do tipo do campo (diferente de min/max, que em texto contam caracteres).

<input name="valor" data-form-mask="currency" data-form-v="required|min_value:0.01|max_value:10000">
<input name="desconto" data-form-v="numeric|positive">
<input name="caixas" data-form-v="integer|multiple_of:6" data-form-msg.multiple_of="Vendemos em caixas de 6.">

Comparação com outro campo

same:campo · different:campo

Igual / diferente do outro campo. Revalida quando o outro muda.

<input name="senha" type="password" data-form-v="required|min:8">
<input name="senha_confirmacao" type="password" data-form-v="required|same:senha"
       data-form-msg.same="As senhas não conferem.">
<input name="nova_senha" type="password" data-form-v="required|different:senha_atual">

greater_than · greater_or_equal · less_than · less_or_equal

Compara números (ou datas, se o campo for de data) com outro campo. Se o outro estiver vazio, passa.

<input name="preco_min" data-form-v="numeric">
<input name="preco_max" data-form-v="numeric|greater_or_equal:preco_min">

Datas

Campos type="date", datetime-local, time, month e week são reconhecidos. Em input de texto, a data é lida em ISO (2026-12-31); para 31/12/2026 use data-form-date-format="br" ou a máscara date. Datas inexistentes (31/02) são recusadas.

date · date:datetime|time|month|week

<input name="nascimento" type="date" data-form-v="required|date">
<input name="vencimento" data-form-date-format="br" data-form-v="required|date">
<input name="data" data-form-mask="date" data-form-v="required|date">

before:x · after:x · before_or_equal:x · after_or_equal:x

x pode ser uma data ISO (2026-01-31), today, now ou o nome de outro campo. A mensagem usa "hoje", a data em formato brasileiro ou o rótulo do outro campo.

<input name="nascimento" type="date" data-form-v="required|before:today">
<input name="entrega" type="date" data-form-v="required|after_or_equal:today">
<input name="checkin" type="date" data-form-v="required|after_or_equal:today">
<input name="checkout" type="date" data-form-v="required|after:checkin">

date_between:inicio,fim

<input name="data_evento" type="date" data-form-v="required|date_between:2026-01-01,2026-12-31">
<input name="data_pagamento" type="date" data-form-v="date_between:emissao,vencimento">

Documentos e contatos (Brasil)

cpf · cnpj · cnpj:numeric · cpf_cnpj

Conferem os dígitos verificadores; aceitam com ou sem pontuação. cnpj aceita o CNPJ alfanumérico (letras nas 12 primeiras posições); cnpj:numeric só o numérico. cpf_cnpj: 11 caracteres = CPF, senão CNPJ.

<input name="cpf" data-form-mask="cpf" data-form-v="required|cpf">
<input name="documento" data-form-mask="cpf_cnpj" data-form-v="required|cpf_cnpj">

cep · telefone · telefone:celular · telefone:fixo

Conferem o formato (8 dígitos; DDD + 8 ou 9 dígitos), não se o CEP ou o número existem.

<input name="cep" data-form-mask="cep" data-form-v="required|cep">
<input name="whatsapp" data-form-mask="celular" data-form-v="required|telefone:celular">

card · card:visa,mastercard,… · luhn

card: dígito de Luhn + comprimento da bandeira (visa, mastercard, amex, elo, hipercard, diners, discover, jcb). Não confere se o cartão existe. luhn: só o dígito.

<input name="cartao" data-form-mask="card" data-form-v="required|card:visa,mastercard,elo">

Arquivos

Só em input type="file". Tamanhos: 500KB, 10MB (decimal: 10.000.000 bytes) ou 10MiB (binário: 10.485.760). Erros por arquivo aparecem também no item da lista.

files_min:n · files_max:n · files_total_max:tam

Quantidade de arquivos (conta os existentes mantidos na edição) / soma dos tamanhos dos novos.

<input type="file" name="fotos[]" multiple data-form-v="required|files_min:2|files_max:10|files_total_max:30MB">

file_min:tam · file_max:tam · non_empty_file

<input type="file" name="contrato" data-form-v="required|file_max:5MB|non_empty_file">

ext:pdf,jpg · mime:application/pdf,image/*

Extensão do nome / tipo informado pelo navegador (aceita curinga image/*). Ambos vêm do nome do arquivo: o servidor precisa conferir o conteúdo.

<input type="file" name="documento" data-form-v="required|ext:pdf,jpg,jpeg,png|mime:application/pdf,image/*">

image · width_min · width_max · height_min · height_max · dimensions:LxA · aspect_ratio:r[,tolerância]

assíncronas Decodificam a imagem no navegador (PNG, JPEG, GIF, WebP, AVIF, BMP). Regras de dimensão ignoram arquivos que não são imagem — use image para exigir imagem.

<input type="file" name="avatar" accept="image/*"
       data-form-v="required|image|file_max:5MB|width_min:200|height_min:200|aspect_ratio:1/1,0.02">
<input type="file" name="banner" data-form-v="image|dimensions:1200x400">

csv, csv_headers, csv_columns, json, json_root, json_keys, pdf_signature, xlsx_signature, media_duration_min, media_duration_max

Exigem o módulo alpine-form-inspectors. Ver Inspetores de arquivo.

Criar sua regra

Regra desconhecida é erro, mas você pode registrar as suas antes de o Alpine iniciar:

AlpineForm.validator('placa', {
    validate: value => /^[A-Z]{3}-?\d[A-Z0-9]\d{2}$/.test(String(value).toUpperCase()),
})
AlpineForm.messages.placa = 'Placa inválida.'
<input name="placa" data-form-v="required|placa">
