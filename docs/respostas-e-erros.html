Respostas e erros

O formato de resposta que o AlpineForm entende, como cada erro do servidor chega ao campo certo, e como ler respostas do Laravel, do Joomla ou de outro formato.

Formato de resposta

Sucesso
HTTP 200
{ "success": true, "message": "Cadastro realizado.", "data": { "id": 15 } }
Erro de validação
HTTP 422
{
  "success": false,
  "message": "Confira os campos destacados.",
  "errors": {
    "email": ["Este e-mail já está em uso."],
    "itens.1.quantidade": "Estoque insuficiente.",
    "": ["Seu plano não permite mais cadastros."]
  }
}
  • message (ou mensagem) aparece em [data-form-status].
  • errors: chave = campo; valor = texto ou lista de textos.
  • data fica em $form.result.data.
  • Opcionais: redirect (com data-form-redirect="response"), request_id (registrado no console em erros), job (processamento).

Sem message, cada tipo tem uma mensagem padrão em português (ex.: 401 → "Sua sessão expirou ou você não tem permissão. Entre novamente e tente outra vez."). Personalize em AlpineForm.configure({ messages: { 'submit.auth': '…' } }) — chaves em Referência rápida.

Resposta HTML

Se o servidor devolve uma página (geralmente a tela de login após a sessão expirar), a mensagem é "O servidor respondeu com uma página HTML em vez de dados. Isso costuma indicar sessão expirada, redirecionamento para login ou erro de proxy." e $form.error.diagnostic traz o trecho e looksLikeLogin.

Erro no campo certo

Chave enviada pelo servidorVai para

jform.title ou jform[title]campo name="jform[title]"
documentos.12º arquivo enviado em name="documentos[]" (mensagem no item da lista e no campo)
interesses.2grupo de checkboxes interesses[]
"", "_", "_general", "*"resumo (erro geral)
campo que não existe na telaresumo — nunca é descartado
  • O campo recebe o erro, fica marcado como tocado e o foco vai para o primeiro campo com erro.
  • Ao editar o campo, o erro do servidor some (data-form-server-errors="clear-on-change", padrão). Com keep, fica até o próximo envio.
  • Se a pessoa alterou o campo enquanto a resposta não chegava, o erro daquele campo é ignorado (era sobre o valor antigo).

Erros gerais e resumo

Erros sem campo, falhas de rede e mensagens de 401/403/5xx vão para $form.generalErrors e para o resumo. Para exibir do seu jeito:

<form x-data x-form action="/api/x" method="post" data-form-summary="none" novalidate>
    <div class="alerta" x-show="$form.generalErrors.length">
        <template x-for="msg in $form.generalErrors"><p x-text="msg"></p></template>
    </div>
    ...
</form>

Laravel

<form x-data x-form action="/clientes" method="post" data-form-response-adapter="laravel" novalidate>

O 422 padrão do Laravel ({ message, errors: { "itens.0.nome": [...] } }) é lido direto; a mensagem genérica em inglês ("The given data was invalid.") é descartada quando há erros por campo. 419 = token CSRF expirado. Controller em Backend › Laravel.

Joomla

<form x-data x-form action="index.php?option=com_loja&amp;task=cliente.salvar&amp;format=json" method="post"
      data-form-response-adapter="joomla" novalidate>

Lê o JsonResponse/JResponseJson: { success, message, messages: { error: [], warning: [] }, data }. As mensagens enfileiradas (enqueueMessage) de erro e aviso vão para o resumo; erros por campo são lidos de data.errors (ex.: { "jform[title]": "Título obrigatório." }). Controller em Backend › Joomla.

Outro formato de API

// API que responde { ok: true, payload: {...} } ou { ok: false, fieldErrors: [{ field, msg }] }
AlpineForm.responseAdapter('minha-api', (raw, ctx) => {
    const base = AlpineForm.registry.get('responseAdapter', 'default')(raw, ctx)
    let json = null
    try { json = JSON.parse(raw.text) } catch (e) { return base }
    if (!json || typeof json.ok !== 'boolean') return base

    const errors = {}
    for (const e of json.fieldErrors || []) {
        if (!errors[e.field]) errors[e.field] = []
        errors[e.field].push(e.msg)
    }
    return {
        ...base,
        ok: json.ok,
        kind: json.ok ? 'success' : (Object.keys(errors).length ? 'validation' : 'logical'),
        message: json.mensagem || null,
        errors,
        data: json.payload ?? null,
    }
})
<form x-data x-form action="/api/x" method="post" data-form-response-adapter="minha-api" novalidate>

Mostrar erros pelo código

const form = AlpineForm.get('cadastro')

form.setErrors({ email: 'Já cadastrado.', 'itens.0.qtd': ['Mínimo 1.'] })     // como se viessem do servidor
form.setErrors(['Erro geral exibido no resumo.'])
form.setErrors({ cpf: 'Inválido.' }, { replace: false })                      // soma aos existentes
form.clearErrors('email')
form.clearErrors()                                                             // todos

Lendo o resultado

<p x-show="$form.success" x-text="$form.result?.message"></p>
<p x-show="$form.failed" class="erro" x-text="$form.error?.message"></p>
<p x-show="$form.error?.kind === 'auth'"><a href="/login">Entrar novamente</a></p>
