Erros e soluções

O que significa cada mensagem de erro, por que aparece e como resolver — e o que fazer quando algo simplesmente não acontece.

Mensagens de configuração aparecem no console com o prefixo [AlpineForm] e em $form.configErrors; o campo afetado mostra "Este campo tem uma configuração inválida e não pode ser validado." e o envio fica bloqueado. Use Ctrl+F com um trecho da mensagem que você recebeu.

Ferramentas no console
AlpineForm.diagnose()                    // formulários que não inicializaram
AlpineForm.get('meuForm').configErrors   // erros de configuração
AlpineForm.get('meuForm').diagnostics()  // regras, máscara e dependências de cada campo

Nada acontece

O formulário não valida nem envia por AJAX

Causas: falta x-data no form (ou num elemento acima); o form está dentro de x-ignore; o Alpine foi carregado antes do alpine-form.min.js; o Alpine nem foi carregado.

Solução: <form x-data x-form …>; carregue o Alpine por último com defer. O console mostra "<form x-form> não foi inicializado…" ou "O Alpine parece já ter sido iniciado; carregue alpine-form antes do Alpine.".

Aparecem os balões de erro do navegador

Solução: acrescente novalidate ao <form>.

O erro não aparece

Causas: o campo ainda não foi "tocado" (no modo live, o erro aparece ao sair do campo ou no envio); modo submit; o campo está desabilitado ou dispensado (data-form-hidden="skip"); o campo não tem name.

Solução: confira $form.fields.<campo> (touched, validated, errors). Veja modos de validação.

Campo adicionado depois não é validado

Causas: sem name; fora do form sem form="id"; controle externo adicionado após a inicialização.

Solução: dê name ao campo; para controles externos chame $form.refresh(). Confira com $form.has('nome').

O erro do servidor não aparece no campo

Causa: a chave em errors não corresponde ao name do campo. Chaves sem campo vão para o resumo ($form.generalErrors).

Solução: use o mesmo nome do HTML (itens[0][nome]) ou a forma com ponto (itens.0.nome). No Joomla, use o adaptador joomla e coloque os erros em data.errors.

Arquivo removido continua sendo enviado

Causa: o envio está sendo feito por código próprio (new FormData(form)), não pelo AlpineForm.

Solução: envie com o botão submit ou $form.submit(); a lista interna é a fonte de verdade.

A barra chega a 100% e fica parada

Causa: comportamento esperado: o arquivo foi enviado e o servidor está processando (fase awaiting).

Solução: mostre [data-form-status] ("Envio concluído. Aguardando resposta do servidor…"). Para processamentos longos, responda 202 e use jobs.

O servidor recebe o valor com máscara (ou sem)

Solução: escolha com data-form-submit-value="raw|formatted|canonical". Confira com $form.getValue('campo', { as: 'submit' }).

Mensagens de configuração

Regra desconhecida "…". Você quis dizer "…"?

Causa: nome de regra errado, regra de um módulo não carregado (csv sem inspetores) ou regra própria registrada depois do Alpine iniciar.

Solução: corrija o nome (veja Regras), carregue o módulo ou registre a regra antes do Alpine.

Atributo desconhecido "data-form-…" no campo "…"

Causa: erro de digitação ou módulo não carregado.

Solução: confira na referência rápida.

data-form-mask requer o módulo de máscaras (alpine-form-masks)

Também: "data-form-chunked requer o módulo de chunks (alpine-form-chunks).". Solução: carregue o script do módulo depois do núcleo e antes do Alpine.

A regra "…" exige N parâmetro(s) · Parâmetro inválido "…" na regra "…"

Exemplos: min sem valor; min:abc; file_max:5 (falta a unidade); after:31/12/2026 (datas literais em ISO: 2026-12-31).

<!-- Errado -->
<input name="a" data-form-v="min">
<input type="file" name="b" data-form-v="file_max:5">
<!-- Certo -->
<input name="a" data-form-v="min:3">
<input type="file" name="b" data-form-v="file_max:5MB">

Combinação contraditória: "required" com "optional"/"nullable"

Solução: remova um dos dois.

Regra "…" repetida em data-form-v · Regra vazia na posição N

Causa: a mesma regra duas vezes, ou || / | no fim. Solução: limpe a lista de regras.

O campo "…" referencia "…", que não existe neste formulário

Causa: same:senha, required_if:tipo,pj etc. com nome errado ou campo que saiu do DOM.

Solução: use o name exato do outro campo (ou a chave com ponto).

A regra "pattern" exige o atributo data-form-pattern · data-form-pattern declarado sem a regra "pattern"

Solução: use os dois juntos: data-form-v="pattern" data-form-pattern="^…$". Outras: "Expressão regular inválida…", "data-form-pattern-flags=… inválido. Flags aceitas: i, m, s, u".

Máscaras só se aplicam a input type="text", "tel" ou "search"

Causa: máscara em type="number" (ou outro tipo). Solução: type="text"; a máscara define o inputmode numérico.

data-form-mask="pattern" exige data-form-mask-pattern · Padrão "…" não possui nenhum token (9, A ou *)

Solução: informe um padrão com ao menos um token: data-form-mask-pattern="AAA-9999".

Valores divergentes de … no grupo "…"

Causa: radios/checkboxes do mesmo grupo com atributos diferentes (ex.: data-form-v distinto em cada um). Solução: declare no primeiro do grupo, ou repita exatamente igual.

Valor "…" inválido em data-form-…. Valores aceitos: …

Também: "Duração inválida…", "Valor booleano inválido…", "Tamanho inválido…", "Unidade de tamanho não reconhecida…". Solução: use um dos valores listados na mensagem. Durações: 250, 250ms, 2s, 1min. Tamanhos: 500KB, 10MB, 2MiB.

Campo sensível com validação remota via GET exporia o valor na URL

Solução: use POST (padrão) ou, conscientemente, data-form-remote-allow-query.

data-form-error-target="…" não encontrou elemento · data-form-summary-target="…" não encontrou elemento

Solução: confira o seletor e se o elemento existe quando o form inicializa.

Campo com data-form-v sem atributo name: não será validado nem enviado

Solução: dê name ao campo (para componentes: data-form-name).

Formulário aninhado dentro de outro <form> detectado

Solução: HTML não permite forms aninhados. Separe os formulários ou use form="id" nos controles.

O campo "…" contém arquivo e a codificação é JSON

Solução: use multipart (padrão), data-form-json-files="metadata" (envia só nome/tamanho/tipo) ou upload em partes.

O campo "…" usa o segmento proibido "__proto__"

Causa: nome de campo com __proto__, prototype ou constructor em JSON (proteção contra prototype pollution). Solução: renomeie o campo.

… "…" já registrado. Use { replace: true } para substituir conscientemente

Causa: o mesmo nome de validador, máscara, transporte… registrado duas vezes (script carregado em duplicidade?). Solução: registre uma vez ou passe { replace: true }.

Este formulário já foi inicializado pelo AlpineForm

Causa: x-form processado duas vezes (Alpine iniciado duas vezes, ou AlpineForm.attach num form que já tem x-form). É só um aviso; o primeiro controlador continua valendo.

pauseUpload() requer o módulo de chunks (alpine-form-chunks)

Também para resumeUpload e getUploadSession. "Nenhum upload em andamento para retomar…" significa que não há envio ativo: para retomar após recarregar, selecione o mesmo arquivo e envie.

Limitações conhecidas

  • Progresso real só com o transporte padrão (XHR); por arquivo, só com upload em partes.
  • Após recarregar, o upload em partes exige selecionar o mesmo arquivo de novo (o navegador não guarda o arquivo).
  • Desfazer (Ctrl+Z) em campos com máscara pode pular estados.
  • Dependências revalidam um nível: se C depende de B e B de A, mudar A revalida B, não C.
  • Mensagens por variante no campo (data-form-msg.min.numeric) não são lidas; use AlpineForm.configure({ messages }).
  • A validação remota usa sempre credentials: 'same-origin'.
  • CEP e telefone conferem formato, não existência; CSV é conferido em amostra.

Lista completa e decisões em docs/limitacoes.md e no doc.html (documentação técnica interna).
