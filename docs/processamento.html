Processamento (jobs)

Quando o servidor aceita o envio e processa depois (importação de planilha, geração de relatório, conversão de vídeo): resposta 202, acompanhamento do progresso sem sobrecarregar o servidor, cancelamento e retomada após recarregar.

Como funciona

Envioo formulário sobe o arquivo normalmente
↓
Servidor responde 202{ "job": { "id", "status_url", "cancel_url" } }
↓
Fase processinga biblioteca consulta status_url em intervalos
↓
succeeded / failed / canceledvira success ou error no formulário

Nenhum atributo é necessário para ativar: basta o servidor responder 202 com job.

Formulário

<form x-data x-form action="/api/importacoes" method="post" enctype="multipart/form-data"
      data-form-job-interval="1s" data-form-job-max-interval="5s" data-form-job-timeout="10min"
      data-form-job-persist novalidate>
    <input name="planilha" type="file" accept=".csv" data-form-v="required|ext:csv|file_max:50MB">

    <button type="submit" :disabled="$form.submitting">Importar</button>
    <button type="button" data-form-cancel>Parar de acompanhar</button>
    <button type="button" x-show="$form.processing" @click="$form.cancelJob().catch(e => alert(e.message))">
        Cancelar importação
    </button>

    <div data-form-progress>
        <progress data-form-progress-bar max="100" aria-label="Progresso"></progress>
        <p data-form-status></p>
        <p x-show="$form.job" x-text="$form.job && $form.job.status"></p>
    </div>

    <template x-if="$form.success && $form.result.data">
        <p>Linhas importadas: <strong x-text="$form.result.data.linhas"></strong></p>
    </template>
</form>
AtributoPadrãoEfeito
data-form-job-interval1,5 sIntervalo inicial entre consultas.
data-form-job-max-interval10 sSem mudanças, o intervalo cresce 1,5× até este limite.
data-form-job-timeout10 minTempo máximo acompanhando ("O processamento está demorando mais que o esperado. Consulte o status mais tarde.").
data-form-job-persistfalsoGuarda o id do job no sessionStorage: ao recarregar, o acompanhamento continua.
data-form-job-url · data-form-job-cancel-url—Modelos com {id} quando a resposta traz só o id: /api/jobs/{id}.

Respostas do servidor

Ao receber o envio
HTTP 202
{ "success": true, "message": "Arquivo recebido. Processando…",
  "job": { "id": "a3c0…", "status_url": "/api/jobs/a3c0…", "cancel_url": "/api/jobs/a3c0…" } }
GET status_url
{ "status": "processing", "progress": 42, "message": "Lendo linhas…" }

{ "status": "succeeded", "progress": 100, "result": { "linhas": 5000 } }

{ "status": "failed", "error": { "message": "Coluna 'valor' ausente." } }
  • status: queued, processing, succeeded, failed ou canceled (outro valor é erro de contrato).
  • progress (0 a 100) é opcional: sem ele, a barra fica indeterminada. Nunca é inventado.
  • result vira $form.result.data no sucesso.
  • Também são aceitos job_id/jobId e statusUrl/cancelUrl.
  • Uma consulta só é feita depois que a anterior terminou. Retry-After é respeitado; até 5 falhas de rede seguidas são toleradas; 404/410 encerra com erro.

Cancelar

AçãoO que faz
data-form-cancel / $form.cancel()Para de acompanhar. O processamento continua no servidor ("Acompanhamento encerrado. O processamento pode continuar no servidor.").
$form.cancelJob()Envia DELETE para cancel_url, pedindo ao servidor para cancelar. O acompanhamento continua até o status virar canceled.

Servidor (PHP)

importacoes.php (resumo)
// 1. recebe o arquivo, guarda, cria o job e responde 202
$id = bin2hex(random_bytes(16));
move_uploaded_file($_FILES['planilha']['tmp_name'], "/dados/importacoes/$id.csv");
$db->insert('jobs', ['id' => $id, 'dono' => $usuarioId, 'status' => 'queued', 'progress' => 0]);

http_response_code(202);
echo json_encode([
    'success' => true,
    'message' => 'Arquivo recebido. Processando…',
    'job' => ['id' => $id, 'status_url' => "/api/jobs/$id", 'cancel_url' => "/api/jobs/$id"],
]);
jobs.php (GET /api/jobs/{id})
$job = $db->fetch('SELECT * FROM jobs WHERE id = ? AND dono = ?', [$id, $usuarioId]);
if (!$job) { http_response_code(404); exit; }

echo json_encode([
    'status' => $job['status'],
    'progress' => (int) $job['progress'],
    'message' => $job['mensagem'],
    'result' => $job['status'] === 'succeeded' ? json_decode($job['resultado'], true) : null,
    'error' => $job['status'] === 'failed' ? ['message' => $job['erro']] : null,
]);

O processamento em si roda num worker (cron, fila, supervisor), que atualiza status e progress. O backend de referência tem uma fila em arquivos e um worker real: server/src/JobQueue.php e php server/bin/worker.php.

Sem o worker rodando, o job fica em queued para sempre: a biblioteca não tem como saber que ninguém está processando, e encerra no data-form-job-timeout.
