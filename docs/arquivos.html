Arquivos

Um ou vários arquivos, remoção antes de enviar, seleção acumulada, arrastar e soltar, preview de imagem, regras de tamanho, tipo e dimensão, e edição com anexos já salvos.

Arquivo único

<form x-data x-form action="/api/upload" method="post" enctype="multipart/form-data" novalidate>
    <label for="contrato">Contrato (PDF até 5 MB)</label>
    <input id="contrato" name="contrato" type="file" accept=".pdf,application/pdf"
           data-form-v="required|file_max:5MB|ext:pdf|mime:application/pdf|non_empty_file"
           data-form-msg.required="Selecione o contrato em PDF.">
    <button type="submit">Enviar</button>
</form>
$arquivo = $_FILES['contrato'] ?? null;
if (!$arquivo || $arquivo['error'] === UPLOAD_ERR_NO_FILE) { /* nenhum arquivo */ }
// confira o conteúdo real: finfo_file(finfo_open(FILEINFO_MIME_TYPE), $arquivo['tmp_name']) === 'application/pdf'

accept só filtra a janela de seleção; quem valida são as regras. Sem arquivo selecionado, uma parte vazia é enviada (o PHP recebe UPLOAD_ERR_NO_FILE), como faria o navegador.

Vários arquivos com lista e remoção

<input id="documentos" name="documentos[]" type="file" multiple accept=".pdf,.jpg,.jpeg,.png"
       data-form-files-append
       data-form-v="required|files_max:5|file_max:10MB|files_total_max:30MB|ext:pdf,jpg,jpeg,png"
       data-form-msg.file_max="Cada arquivo pode ter no máximo :max.">
<div data-form-file-list="documentos[]"></div>
  • data-form-file-list mostra a lista com nome, tamanho, miniatura (imagens), erros por arquivo e botão Remover.
  • Remover tira o arquivo do envio, mesmo que o navegador não permita alterar o input.files.
  • data-form-files-append: cada nova seleção soma à lista (sem ele, substitui).
  • Arquivos repetidos (mesmo nome, tamanho e data) são ignorados; para aceitar, data-form-files-duplicates="allow".
  • Erros por arquivo (file_max, ext…) aparecem no item da lista e no campo.
No PHP, $_FILES em formato de lista
foreach ($_FILES['documentos']['name'] as $i => $nome) {
    $tmp = $_FILES['documentos']['tmp_name'][$i];
    $erro = $_FILES['documentos']['error'][$i];
    if ($erro !== UPLOAD_ERR_OK) continue;
    // ... valide e mova ...
}
// erro para o 2º arquivo: $errors['documentos.1'][] = 'Arquivo corrompido.';

Lista montada por você

Prefere seu próprio HTML? Use $form.fields.<campo>.files e $form.removeFile():

<input name="anexos[]" type="file" multiple data-form-files-append data-form-v="files_max:3">
<ul>
    <template x-for="arq in ($form.fields.anexos?.files || [])" :key="arq.id">
        <li>
            <img x-show="arq.previewUrl" :src="arq.previewUrl" width="40" alt="">
            <span x-text="arq.name"></span> (<span x-text="arq.sizeText"></span>)
            <span class="erro" x-text="arq.errors.join(' ')"></span>
            <button type="button" @click="$form.removeFile('anexos', arq.id)">Remover</button>
        </li>
    </template>
</ul>

Cada item: { id, name, size, sizeText, type, previewUrl, errors }.

Arrastar e soltar

<input id="fotos" name="fotos[]" type="file" multiple accept="image/*" data-form-files-append data-form-v="files_max:10|image">
<div class="dropzone" data-form-dropzone="fotos[]">Arraste as fotos para cá</div>
<div data-form-file-list="fotos[]"></div>

Enquanto um arquivo é arrastado sobre a área, ela recebe a classe af-dropzone--over. A área é um complemento: o input continua acessível pelo teclado.

Imagem com preview e dimensões

<input id="foto" name="foto" type="file" accept="image/png,image/jpeg,image/webp"
       data-form-v="required|image|file_max:5MB|width_min:200|height_min:200|aspect_ratio:1/1,0.02"
       data-form-msg.aspect_ratio="A foto precisa ser quadrada.">
<div data-form-file-list="foto"></div>
  • Regras de dimensão decodificam a imagem no navegador (PNG, JPEG, GIF, WebP, AVIF, BMP); o campo fica "validando" por um instante.
  • Miniaturas só para imagens até 20 MB e nunca para SVG (pode conter código). Desligue com data-form-preview="false".
  • As miniaturas são liberadas da memória ao remover, limpar, resetar ou destruir o formulário.

Adicionar arquivos pelo código

<button type="button" @click="$form.addFiles('relatorio', [new File(['a;b\n1;2'], 'relatorio.csv', { type: 'text/csv' })])">
    Gerar CSV de exemplo
</button>
Colar imagem da área de transferência
document.addEventListener('paste', event => {
    const imagens = Array.from(event.clipboardData.files).filter(f => f.type.startsWith('image/'))
    if (imagens.length) AlpineForm.get('perfil').addFiles('foto', imagens)
})

Edição com arquivos já salvos

Arquivos existentes são renderizados pelo servidor. "Remover" um deles gera um pedido de remoção enviado junto, separado dos arquivos novos:

<form x-data x-form action="/api/perfil" method="post" enctype="multipart/form-data" novalidate>
    <ul>
        <li data-form-existing="anexos[]" data-form-existing-id="101" data-form-existing-name="contrato.pdf">
            contrato.pdf <button type="button" data-form-existing-remove>Remover / desfazer</button>
        </li>
        <li data-form-existing="anexos[]" data-form-existing-id="102" data-form-existing-name="rg.jpg">
            rg.jpg <button type="button" data-form-existing-remove>Remover / desfazer</button>
        </li>
    </ul>

    <input name="anexos[]" type="file" multiple data-form-files-append
           data-form-existing-remove-name="anexos_remover[]"
           data-form-v="required|files_max:4|file_max:10MB"
           data-form-msg.required="Mantenha ou envie pelo menos um anexo.">
    <div data-form-file-list="anexos[]"></div>
    <button type="submit">Salvar</button>
</form>
  • O item marcado para remoção recebe a classe af-existing--removed e o botão aria-pressed="true". Clicar de novo desfaz.
  • No envio vão os arquivos novos em anexos[] e os ids removidos em anexos_remover[] (padrão: <nome>_remover[]).
  • required, files_min e files_max contam os existentes mantidos + os novos.
  • O servidor precisa conferir se os ids pertencem ao registro antes de apagar.
  • Pelo código: $form.removeExisting('anexos', '101') alterna; $form.removeExisting('anexos', '101', false) desfaz.

Limites do servidor

O PHP recusa uploads acima de upload_max_filesize e corpos acima de post_max_size antes do seu código rodar (com post_max_size estourado, $_POST e $_FILES chegam vazios). Mantenha file_max/files_total_max abaixo desses limites, ou use o upload em partes. Proxies (nginx client_max_body_size) respondem 413, que o AlpineForm mostra como "Os dados enviados excedem o limite aceito pelo servidor.".

Extensão, tipo e até dimensões conferidos no navegador podem ser falsificados. O servidor deve conferir o conteúdo real (finfo, getimagesize), renomear o arquivo e guardá-lo fora da pasta pública.
