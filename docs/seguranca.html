Segurança

Uso em ambientes regulados (bancos, saúde, governo): CSP estrita sem unsafe-eval, console silencioso, nada gravado no navegador, o que a biblioteca protege e o que continua sendo responsabilidade do servidor.

Primeiro princípio

Validação no navegador é conforto, não proteção: pode ser desligada por qualquer pessoa. Limites, permissões, saldo, antifraude e a validação de cada campo precisam existir no servidor. A biblioteca não passou por auditoria externa nem por teste de invasão.

Configuração recomendada

seguranca.js (carregado depois de alpine-form e antes do Alpine)
AlpineForm.configure({
    log: 'none',         // nada no console (nem erros, nem request_id, nem diagnósticos)
    storage: 'none',     // nada em localStorage/sessionStorage, mesmo com chunk-persist/job-persist
    idempotency: true,   // Idempotency-Key em todo envio (evita operação duplicada)
    credentials: 'same-origin',
})

As duas primeiras opções também valem por formulário: data-form-log="none" e data-form-storage="none".

CSP estrita (sem unsafe-eval)

O AlpineForm não usa eval, new Function, innerHTML nem document.write. Quem precisa de 'unsafe-eval' é o Alpine padrão (ele avalia expressões como :disabled="…"). Com a versão CSP do Alpine (@alpinejs/csp), a página funciona com esta política — testada no Chrome sem nenhuma violação, inclusive com Trusted Types:

Content-Security-Policy
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' blob: data:;
media-src 'self' blob:; connect-src 'self'; form-action 'self'; base-uri 'none';
frame-ancestors 'none'; object-src 'none'; require-trusted-types-for 'script'
  • img-src blob: é necessário para miniaturas de imagens; media-src blob: para a regra de duração de mídia. Sem preview/mídia, pode remover.
  • O CSS da biblioteca é um arquivo (style-src 'self' basta); a barra de progresso usa element.style, permitido pela CSP.

app.js
document.addEventListener('alpine:init', () => {
    window.Alpine.data('cadastro', () => ({
        tipo: 'pf',
        get ehPj() { return this.tipo === 'pj' },
        init() {
            // x-model não funciona na versão CSP; o evento form:change informa o valor
            this.$el.addEventListener('form:change', e => {
                if (e.detail.name === 'tipo') this.tipo = e.detail.value
            })
        },
    }))
})

O que a biblioteca protege

RiscoProteção
XSS por mensagensMensagens (inclusive do servidor) e nomes de arquivo inseridos como texto; HTML nunca é interpretado.
Vazamento do token CSRFEnviado só para a mesma origem. URLs de status e cancelamento de jobs vindas do servidor só são aceitas na mesma origem.
Dados sensíveistype="password" e data-form-sensitive: valor nunca no estado, eventos, mensagens ou URL; GET remoto bloqueado.
Operação duplicada (pagamento em dobro)POST nunca é reenviado automaticamente; resultado desconhecido é informado como tal; Idempotency-Key opcional; clique duplo não gera segunda requisição.
Redirecionamento abertoSó http(s) da mesma origem ou de data-form-redirect-origins.
Prototype pollutionNomes de campo e chaves de erro __proto__, prototype, constructor recusados/neutralizados.
Regex abusivaPadrões até 500 caracteres, flags restritas, entrada até 2000 caracteres.
Arquivos com códigoPreview só de imagens raster (SVG nunca); object URLs revogados.
Configuração erradaRegra/atributo desconhecido bloqueia o envio (nunca envia "sem validar").
Dados de cliente no consoleO trecho de respostas HTML inesperadas nunca vai para o console (fica só em $form.error.diagnostic); com log: 'none', nada é escrito.
Dados no navegadorO núcleo nunca grava valores de campos. O módulo opcional de rascunho grava (exceto senhas, sensíveis e arquivos) só nos formulários com data-form-rascunho. Com storage: 'none', nada é gravado: nem rascunho, nem metadados (nome de arquivo, id de job).
Cadeia de dependênciasNenhuma dependência em tempo de execução além do Alpine.

O que continua sendo do servidor

  • Revalidar tudo e autorizar cada operação (o registro pertence ao usuário?).
  • CSRF em toda rota que altera dados; sessão com cookie HttpOnly, Secure, SameSite.
  • Limitar tentativas: a validação remota ("e-mail já cadastrado") permite descobrir quem é cliente; aplique limite por IP/sessão ou não use em telas públicas.
  • Conteúdo real dos arquivos (finfo, getimagesize), tamanho, nome novo, fora da pasta pública.
  • Idempotência das operações financeiras (exemplo).
  • Cabeçalhos: CSP, X-Content-Type-Options: nosniff, Referrer-Policy, frame-ancestors/X-Frame-Options, HSTS.
  • Cartão de crédito: para escopo PCI reduzido, use o campo hospedado do gateway de pagamento em vez de um input da sua página (a máscara card mantém o número no DOM enquanto é digitado, como qualquer input).

Checklist antes de publicar

  1. AlpineForm.configure({ log: 'none', storage: 'none' }) em produção.
  2. Sem data-form-debug no HTML de produção.
  3. Versão CSP do Alpine + CSP sem 'unsafe-eval'/'unsafe-inline'; teste com securitypolicyviolation no console.
  4. Scripts servidos pelo seu domínio (sem CDN de terceiros) ou com integrity (SRI).
  5. Nenhum ouvinte de form:submit enviando event.detail.request.headers para analytics (contém o token CSRF).
  6. Endpoints de validação remota com limite de tentativas.
  7. Toda regra do formulário também validada no servidor.
  8. Revisão de segurança e teste de invasão da aplicação completa.
