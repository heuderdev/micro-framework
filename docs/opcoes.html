Selects dependentes

Opções de um select vindas da API e que dependem de outros campos — UF → cidade → bairro, categoria → produto, empresa → filial — só com atributos. Requer alpine-form-opcoes.

Instalação

<script src="/js/alpine-form/alpine-form.min.js"></script>
<script src="/js/alpine-form/alpine-form-opcoes.min.js"></script>   <!-- depois do núcleo -->
<script defer src="/js/alpine.min.js"></script>
ESM
import opcoes from 'alpine-form/opcoes'
AlpineForm.use(opcoes)

Exemplo executável: examples/opcoes.php.

UF → cidade → bairro

<form x-data x-form action="/api/enderecos" method="post" novalidate>
    <select name="uf" data-form-opcoes="/api/ufs" data-form-v="required">
        <option value="">Selecione</option>
    </select>

    <select name="cidade" data-form-opcoes="/api/cidades?uf={uf}" data-form-v="required">
        <option value="">Escolha a UF primeiro</option>
    </select>

    <select name="bairro" data-form-opcoes="/api/bairros?cidade={cidade}">
        <option value="">Escolha a cidade primeiro</option>
    </select>
    <button type="submit">Salvar</button>
</form>
  1. Ao abrir, uf busca /api/ufs (não depende de ninguém).
  2. {uf} é trocado pelo valor do campo uf. Enquanto ele estiver vazio, cidade fica sem opções e desabilitado (campo desabilitado não valida nem é enviado).
  3. Escolheu a UF: cidade busca /api/cidades?uf=SP. Trocou a UF: a lista antiga some na hora, a requisição anterior é cancelada e a resposta antiga nunca sobrescreve a nova.
  4. Se o valor escolhido não existe na lista nova, o campo é limpo — e isso limpa o bairro. A cadeia se propaga sozinha.
  5. A <option value=""> escrita no HTML é o placeholder: fica sempre.

O que o servidor responde

FormatoExemplo
Lista de objetos[{ "id": 3550308, "nome": "São Paulo" }, …]
Laravel / Resource{ "data": [{ "id": 1, "name": "…" }] }
Contrato AlpineForm / Joomla{ "success": true, "data": [...] } ou { "success": true, "data": { "opcoes": [...] } } (também itens, items, options)
Mapa valor → texto{ "SP": "São Paulo", "RJ": "Rio de Janeiro" }
Lista de textos["Sé", "Mooca", "Pinheiros"] (valor = texto)

Em objetos, o valor é lido de value, id, codigo, sigla ou key; o texto, de label, text, nome, name, descricao ou titulo. Para outros nomes:

<select name="categoria" data-form-opcoes="/api/categorias"><option value="">Categoria</option></select>
<select name="produto" data-form-opcoes="/api/produtos?categoria={categoria}"
        data-form-opcoes-valor="sku" data-form-opcoes-texto="descricao_curta"></select>
PHP puro
<?php
// /api/cidades?uf=SP — valide o parâmetro: ele vem da URL
$uf = strtoupper($_GET['uf'] ?? '');
if (!preg_match('/^[A-Z]{2}$/', $uf)) { http_response_code(422); exit; }
$st = $pdo->prepare('SELECT id, nome FROM cidades WHERE uf = ? ORDER BY nome');
$st->execute([$uf]);
header('Content-Type: application/json; charset=utf-8');
echo json_encode($st->fetchAll(PDO::FETCH_ASSOC), JSON_UNESCAPED_UNICODE);
Laravel
Route::get('/api/cidades', fn (Request $r) =>
    Cidade::where('uf', $r->validate(['uf' => 'required|size:2'])['uf'])->orderBy('nome')->get(['id', 'nome'])
);

O usuário pode chamar o endpoint com qualquer parâmetro e enviar qualquer valor no formulário. No salvamento, confira de novo que a cidade pertence à UF (Validador::em() nos Helpers PHP, Rule::exists no Laravel).

Formulário de edição (valores já salvos)

<select name="uf" data-form-opcoes="/api/ufs">
    <option value="">Selecione</option>
    <option value="RJ" selected>Rio de Janeiro</option>        <!-- renderizado pelo servidor: aparece antes do JS -->
</select>
<select name="cidade" data-form-opcoes="/api/cidades?uf={uf}" data-form-opcoes-selecionado="3303302">
    <option value="">Escolha a UF primeiro</option>
</select>
<select name="bairro" data-form-opcoes="/api/bairros?cidade={cidade}" data-form-opcoes-selecionado="Icaraí">
    <option value="">Escolha a cidade primeiro</option>
</select>

O valor inicial é o de data-form-opcoes-selecionado ou o da <option selected> que o servidor renderizou. As listas carregam em cadeia e cada valor é selecionado quando a sua lista chega. As opções estáticas com valor são substituídas pela lista da API na primeira carga.

Outras dependências

  • Vários campos: data-form-opcoes="/api/turmas?curso={curso}&turno={turno}" — só busca quando todos estiverem preenchidos.
  • Campo de texto (código, CEP): espera a digitação parar (data-form-opcoes-debounce, padrão 250 ms). Selects, radios e checkboxes buscam na hora.
  • Nomes com colchetes: {endereco[uf]} ou {endereco.uf}.
  • Campo com máscara: vai o valor de envio — o mesmo que o servidor recebe no submit (veja data-form-submit-value em Máscaras).
  • Sem dependência: data-form-opcoes="/api/bancos" só carrega a lista uma vez ao abrir.

Em linhas repetidas (x-for)

<form x-data="{ linhas: [1] }" x-form action="/api/pedido" method="post" novalidate>
    <template x-for="(n, i) in linhas" :key="n">
        <div>
            <select :name="'itens[' + i + '][categoria]'" data-form-opcoes="/api/categorias"><option value="">Categoria</option></select>
            <select :name="'itens[' + i + '][produto]'" :data-form-opcoes="'/api/produtos?categoria={itens[' + i + '][categoria]}'">
                <option value="">Produto</option>
            </select>
        </div>
    </template>
    <button type="button" @click="linhas.push(linhas.length + 1)">Adicionar item</button>
</form>

Cada linha tem a sua cadeia. Linhas adicionadas depois são reconhecidas sozinhas; linhas removidas liberam requisições e listeners.

Grupos, lista vazia e select múltiplo

<select name="uf" data-form-opcoes="/api/ufs"><option value="">UF</option></select>
<select name="cidade" data-form-opcoes="/api/cidades?uf={uf}"
        data-form-opcoes-grupo="regiao"
        data-form-opcoes-vazio="Nenhuma cidade para esta UF">
    <option value="">Escolha a UF</option>
</select>

<select name="empresa" data-form-opcoes="/api/empresas"><option value="">Empresa</option></select>
<select name="filiais[]" multiple data-form-opcoes="/api/filiais?empresa={empresa}"></select>
  • data-form-opcoes-grupo="regiao" agrupa em <optgroup> pelo campo indicado.
  • data-form-opcoes-vazio: texto de uma opção desabilitada quando a API devolve lista vazia (o select também fica desabilitado).
  • Select múltiplo mantém os valores que continuam existindo na nova lista.

Carregando e erro

select[data-form-opcoes-estado="carregando"] { cursor: progress; opacity: .7; }   /* já em alpine-form.css */
select[data-form-opcoes-estado="erro"] { border-color: #b91c1c; }
<form x-data="{ falhou: false }" x-form @form:opcoes-erro="falhou = true" @form:opcoes-carregadas="falhou = false" novalidate>
    <select name="uf" data-form-opcoes="/api/ufs"><option value="">UF</option></select>
    <p x-show="falhou" role="alert">Não foi possível carregar as opções. <button type="button" @click="AlpineForm.opcoes.recarregar($el.closest('form'))">Tentar de novo</button></p>
</form>
  • data-form-opcoes-estado: aguardando (falta dependência), carregando, pronto ou erro. Durante a carga o select tem aria-busy="true".
  • Em erro (rede, HTTP, resposta que não é JSON ou formato desconhecido) o select volta a ficar habilitado, sem opções; o erro vai ao console (respeita data-form-log="none").
  • Eventos no form: form:opcoes-carregadas ({ name, total, url }) e form:opcoes-erro ({ name, url, status }).
  • Um select desabilitado pelo seu HTML ou pelo Alpine nunca é reabilitado pelo módulo. Para não desabilitar enquanto espera: data-form-opcoes-manter-habilitado.

Cache

As listas ficam na memória da página por URL (até 100): voltar para uma UF já escolhida não repete a requisição, e vários selects com a mesma URL compartilham a resposta. Nada é gravado em localStorage. Desligue com data-form-opcoes-cache="false" (dados que mudam a todo momento) ou force: AlpineForm.opcoes.recarregar(form, 'cidade'); AlpineForm.opcoes.limparCache() esvazia tudo.

Referência

Atributo (no select)PadrãoEfeito
data-form-opcoesobrigatórioURL (mesma origem) com {campo} para cada dependência.
data-form-opcoes-valor · data-form-opcoes-textoautomáticoCampos do item usados como valor e texto.
data-form-opcoes-grupo—Campo do item que agrupa em <optgroup>.
data-form-opcoes-selecionado—Valor a selecionar na primeira carga (edição).
data-form-opcoes-vazio—Texto mostrado quando a lista vem vazia.
data-form-opcoes-debounce250msEspera quando a dependência é um campo de texto.
data-form-opcoes-cachetruefalse busca sempre.
data-form-opcoes-manter-habilitadofalseNão desabilita enquanto espera/carrega.

Global: AlpineForm.opcoes.recarregar(formOuId, nome?), AlpineForm.opcoes.estado(formOuId, nome) ({ carregando, erro, url }), AlpineForm.opcoes.selecionar(formOuId, nome, valor) (seleciona agora ou quando a lista chegar — usado pelo autopreenchimento), AlpineForm.opcoes.controla(formOuId, nome), AlpineForm.opcoes.limparCache(). Mensagem: AlpineForm.messages['opcoes.erro'].

Erros de configuração bloqueiam o envio e aparecem no console: {campo} inexistente, URL de outra origem (use um endpoint do próprio site como proxy), atributo fora de <select>, duração inválida, select que depende dele mesmo.
