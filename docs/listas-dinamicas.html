Listas e DOM dinâmico

Linhas que o usuário adiciona e remove, campos criados pelo Alpine, regras que mudam, vários formulários na mesma página e estado exibido fora do form.

Tudo é detectado sozinho

O AlpineForm observa o formulário. Quando um campo entra (x-for, x-if, HTML injetado), sai, ou tem name, data-form-v, data-form-mask, disabled, type alterados, ele se atualiza: campos novos passam a ser validados e enviados; campos removidos têm erros, estado e listeners limpos.

Linhas repetidas (x-for)

<form x-data="{ itens: [{ id: 1 }], seq: 1 }" x-form action="/api/pedido" method="post" novalidate>
    <template x-for="(item, index) in itens" :key="item.id">
        <div class="linha">
            <input :name="`itens[${index}][produto]`" data-form-label="Produto" data-form-v="required|min:2">
            <input :name="`itens[${index}][quantidade]`" data-form-label="Quantidade" inputmode="numeric"
                   data-form-v="required|integer|min_value:1">
            <button type="button" @click="itens.splice(index, 1)" :disabled="itens.length === 1">Remover</button>
        </div>
    </template>

    <button type="button" @click="itens.push({ id: ++seq })">Adicionar item</button>
    <button type="submit">Enviar</button>
</form>
  • Use :key com um id estável (não o índice): assim o Alpine reaproveita o elemento e o campo mantém valor, estado e erros.
  • Os nomes são reindexados pelo próprio x-for (itens[0], itens[1]…); o campo acompanha o novo nome.
  • data-form-label evita mensagens como "O campo itens[0][produto] é obrigatório.".
  • Um erro do servidor itens.1.quantidade aparece na segunda linha; se uma linha acima for removida, a mensagem continua na linha certa.
Mínimo e máximo de linhas com um campo de controle
<input type="hidden" name="total_itens" :value="itens.length" data-form-v="integer|min_value:1|max_value:20"
       data-form-msg.min_value="Adicione pelo menos um item." data-form-msg.max_value="No máximo 20 itens.">

Regras que mudam

<form x-data="{ tipo: 'pf' }" x-form action="/cliente" method="post" novalidate>
    <select name="tipo" x-model="tipo"><option value="pf">Física</option><option value="pj">Jurídica</option></select>

    <input name="documento"
           :data-form-mask="tipo === 'pf' ? 'cpf' : 'cnpj'"
           :data-form-v="tipo === 'pf' ? 'required|cpf' : 'required|cnpj'"
           :data-form-label="tipo === 'pf' ? 'CPF' : 'CNPJ'">
</form>

Ao trocar o tipo, a máscara e as regras são reaplicadas; se o campo já tinha sido validado, é revalidado na hora.

HTML injetado e controles externos

Campos inseridos com innerHTML/insertAdjacentHTML dentro do form são detectados. Se você mudar algo que o AlpineForm não observa, ou adicionar um controle fora do form com form="id", chame $form.refresh():

document.getElementById('lateral').insertAdjacentHTML('beforeend', '<input name="obs" form="pedido" data-form-v="max:200">')
AlpineForm.get('pedido').refresh()

Vários formulários na página

<form id="login" x-data x-form action="/login" method="post" novalidate>
    <input name="email" data-form-v="required|email">
</form>
<form id="newsletter" x-data x-form action="/newsletter" method="post" novalidate>
    <input name="email" data-form-v="required|email">
</form>

Cada um tem estado próprio: $form dentro de cada form se refere a ele. Pelo código: AlpineForm.get('login'), AlpineForm.get('newsletter').

Formulários aninhados (<form> dentro de <form>) não existem em HTML válido e geram erro. Use controles com form="id" ou separe os formulários.

Estado fora do form (data-form-for)

Barra de progresso no rodapé, botão de envio na barra fixa, lista de arquivos num painel lateral: marque o contêiner com data-form-for="idDoForm". Dentro dele, $form e os atributos data-form-status, data-form-progress-*, data-form-cancel, data-form-file-list e data-form-dropzone funcionam como se estivessem no form.

<form id="perfil" x-data x-form action="/perfil" method="post" novalidate>
    <input name="nome" data-form-v="required">
    <input type="file" name="foto" data-form-v="image">
</form>

<footer x-data data-form-for="perfil">
    <span data-form-status></span>
    <div data-form-file-list="foto"></div>
    <button type="submit" form="perfil" :disabled="$form.submitting">Salvar</button>
    <button type="button" data-form-cancel>Cancelar</button>
</footer>

O x-data no contêiner externo é necessário para o Alpine processar $form e :disabled ali. O botão usa o atributo HTML form="perfil" para enviar o formulário.

Remover o formulário

Quando o Alpine remove o form (por x-if, troca de página em SPA, etc.), tudo é liberado: listeners, observador, consultas em andamento, previews de imagem, elementos de erro criados e atributos ARIA adicionados. Se você remover o form por fora do Alpine, chame antes $form.destroy().
