Helpers PHP

Um arquivo PHP sem dependências (PHP 7.0 a 8.x, inclusive Joomla 3) que tira a repetição do backend: respostas no contrato do AlpineForm, leitura do corpo em qualquer codificação, validação com mensagens em português e parâmetros de listagem seguros para o x-lista.

Instalação

Copie php/alpine-form.php para o projeto (ou use direto de node_modules/alpine-form/php/alpine-form.php) e inclua:

<?php
require_once __DIR__ . '/lib/alpine-form.php';

use AlpineForm\Helpers\Resposta;
use AlpineForm\Helpers\Entrada;
use AlpineForm\Helpers\Validador;
use AlpineForm\Helpers\Consulta;
use AlpineForm\Helpers\Csrf;
ClassePara quê
RespostaJSON de sucesso, erro de validação (422), erro geral e processamento posterior (202).
EntradaLê o que o formulário mandou — JSON, urlencoded ou multipart — com nomes aninhados.
ValidadorRegras comuns (obrigatório, tamanho, e-mail, CPF, CNPJ, CEP, telefone, decimal, data…) e erros com a chave certa para cada campo.
ConsultaPágina, tamanho, ordenação (lista branca) e filtros de uma listagem; resposta no formato do x-lista.
CsrfToken por sessão para PHP puro (no Joomla e no Laravel use o do framework).

Cadastro completo (PHP puro)

cliente-salvar.php
<?php
require_once __DIR__ . '/lib/alpine-form.php';
use AlpineForm\Helpers\{Resposta, Entrada, Validador, Csrf};   // PHP 7.0+: use agrupado

if (!Csrf::valido()) {
    Resposta::enviar(Resposta::erro('Sessão expirada. Recarregue a página.', 419));
}

$entrada = Entrada::ler();                       // funciona com data-form-encoding json, urlencoded ou multipart
$v = new Validador($entrada);
$v->obrigatorio('nome')->tamanho('nome', 3, 80)
  ->obrigatorio('email')->email('email')
  ->obrigatorio('cpf')->cpf('cpf')
  ->obrigatorio('uf')->em('uf', ['SP', 'RJ', 'MG'])
  ->decimal('limite', 2, '0', '50000.00')        // opcional: só valida se veio preenchido
  ->data('nascimento', 'Y-m-d', null, 'hoje');

if (!$v->temErro('email') && emailJaCadastrado($entrada->texto('email'))) {
    $v->erro('email', 'Este e-mail já está cadastrado.');
}
if ($v->falhou()) {
    Resposta::enviar(Resposta::invalido($v->erros()));   // 422 { success:false, message, errors:{campo:[...]} }
}

$id = salvarCliente($entrada->texto('nome'), $entrada->digitos('cpf'));
Resposta::enviar(Resposta::sucesso(['id' => $id], 'Cliente cadastrado.'));
Página com o formulário
<?php require_once __DIR__ . '/lib/alpine-form.php'; use AlpineForm\Helpers\Csrf; ?>
<meta name="csrf-token" content="<?= htmlspecialchars(Csrf::token()) ?>">

<form x-data x-form action="/cliente-salvar.php" method="post" data-form-lista="clientes" novalidate>
    <input name="nome" data-form-v="required|min:3|max:80">
    <input name="email" type="email" data-form-v="required|email">
    <input name="cpf" data-form-mask="cpf" data-form-v="required|cpf">
    <select name="uf" data-form-v="required"><option value="">--</option><option>SP</option><option>RJ</option><option>MG</option></select>
    <button type="submit">Salvar</button>
    <p data-form-status></p>
</form>

As mesmas regras no navegador (para o usuário) e no servidor (para valer). Os erros do servidor aparecem embaixo de cada campo; o que não tiver campo vai para o resumo.

Resposta

MétodoGera
Resposta::sucesso($dados, $mensagem, $status = 200){ "success": true, "message": "…", "data": … }
Resposta::invalido($erros, $mensagem)HTTP 422 { "success": false, "message": "Confira os campos destacados.", "errors": { "campo": ["…"] } } — aceita mensagem única ou lista; chave "" ou "_" vai para o resumo geral.
Resposta::erro($mensagem, $status = 400, $dados = null)Erro sem campo (regra de negócio, 403, 409…). Não coloque detalhes internos (SQL, caminhos) na mensagem.
Resposta::aceito($jobId, $statusUrl, $cancelUrl)HTTP 202 com job — o formulário acompanha o processamento.
Resposta::enviar([$status, $corpo])Envia com Content-Type: application/json; charset=utf-8, X-Content-Type-Options: nosniff, Cache-Control: no-store e encerra (Resposta::$semExit = true para não encerrar).
Resposta::json($corpo)Só o texto JSON (acentos preservados; UTF-8 inválido não gera resposta vazia).

Os métodos devolvem [status, corpo] sem enviar nada: dá para testar, registrar ou adaptar (ex.: return response()->json($corpo, $status) no Laravel).

Entrada

$e = Entrada::ler();
$e->texto('nome');               // aparado; '' se ausente
$e->texto('cliente[nome]');      // nomes do HTML...
$e->get('cliente.nome');         // ...ou com ponto
$e->get('itens.0.qtd');          // linhas de listas dinâmicas
$e->digitos('cpf');              // "123.456.789-09" → "12345678909" (com ou sem máscara)
$e->lista('interesses');         // checkbox[] / select múltiplo → sempre array
$e->todos();                     // array completo

Validador

Encadeie as regras. Todas, exceto obrigatorio, ignoram campo vazio (campo opcional). Depois do primeiro erro de um campo, as demais regras desse campo não acrescentam mensagens — o usuário vê um problema por vez, como no navegador.

RegraEquivalente no HTMLMensagem padrão
obrigatorio($campo)requiredPreencha este campo.
tamanho($campo, $min, $max)min:3|max:80Use pelo menos :min / no máximo :max caracteres. (conta caracteres, não bytes)
email, cpf, cnpj, cpfOuCnpj, cep, telefone, urlemail, cpf, cnpj, cpf_cnpj…Informe um e-mail válido. / CPF inválido. … (url só aceita http e https)
inteiro($campo, $min, $max)integerInforme um número inteiro.
decimal($campo, $casas, $min, $max)decimal:2 (máscara moeda envia "1234.50")Comparação exata em texto, nunca float: passe limites como texto ('0.01').
em($campo, $opcoes)in: / selectEscolha uma opção válida. (vale também para listas)
data($campo, $formato, $min, $max)date, after, beforeFormato padrão Y-m-d (input date); limites no mesmo formato ou 'hoje'. 30/02 é rejeitado.
igual($campo, $outro)same:senhaOs valores não conferem.
regex($campo, $padrao), regra($campo, $msg, $nome, fn)regra própriaFormato inválido.
erro($campo, $mensagem)—Erro seu (duplicidade, regra de negócio).

Toda regra aceita uma mensagem própria como último argumento: $v->obrigatorio('nome', 'Informe o nome completo.'). Para mudar o padrão de todo o sistema: Validador::$mensagens['obrigatorio'] = 'Campo obrigatório.'.

Itens de uma lista dinâmica (itens[0][produto], itens[1][produto]...)
$v->cadaItem('itens', function (Validador $item, $indice) {
    $item->obrigatorio('produto')->inteiro('qtd', 1, 999)->decimal('preco', 2, '0.01');
});
// erros: { "itens.1.produto": ["Preencha este campo."] } → aparece no campo da linha 2

Nomes com colchetes viram ponto nos erros (jform[nome] → jform.nome), formato que o AlpineForm associa ao campo.

Consulta (listagens)

Lê page, per_page, sort, direction e os filtros do x-lista sem confiar em nada: página e tamanho com limites, ordenação só pelas colunas permitidas, filtros com tipo.

api/clientes.php (PDO)
<?php
require_once __DIR__ . '/../lib/alpine-form.php';
use AlpineForm\Helpers\{Consulta, Resposta};

$c = Consulta::ler($_GET, [
    'ordenaveis' => ['nome' => 'c.nome', 'cadastro' => 'c.criado_em', 'saldo' => 'c.saldo'],   // parâmetro => coluna
    'ordem' => 'nome',
    'por_pagina' => 20,
    'por_pagina_max' => 100,
]);

$where = ['1 = 1'];
$params = [];
if ($busca = $c->like('busca')) {                                   // % e _ digitados viram literais
    $where[] = "(c.nome LIKE ? ESCAPE '\\\\' OR c.email LIKE ? ESCAPE '\\\\')";
    array_push($params, "%$busca%", "%$busca%");
}
if ($uf = $c->opcao('uf', ['SP', 'RJ', 'MG'])) { $where[] = 'c.uf = ?'; $params[] = $uf; }
if ($status = $c->opcoes('status', ['ativo', 'inativo', 'pendente'])) {
    $where[] = 'c.status IN (' . implode(',', array_fill(0, count($status), '?')) . ')';
    $params = array_merge($params, $status);
}
if ($de = $c->data('de')) { $where[] = 'c.criado_em >= ?'; $params[] = $de; }

$filtro = implode(' AND ', $where);
$total = $pdo->prepare("SELECT COUNT(*) FROM clientes c WHERE $filtro");
$total->execute($params);

$linhas = $pdo->prepare("SELECT c.id, c.nome, c.email, c.uf, c.status FROM clientes c
                         WHERE $filtro ORDER BY {$c->sqlOrdem('c.id')} {$c->sqlLimite()}");
$linhas->execute($params);

Resposta::enviar([200, $c->resposta($linhas->fetchAll(PDO::FETCH_ASSOC), (int) $total->fetchColumn())]);
MétodoDevolve
pagina(), porPagina(), offset()Inteiros já limitados (página 1 a 10000; tamanho 1 a por_pagina_max).
ordem(), direcao(), coluna()Nome público aceito, asc/desc e a coluna SQL da lista branca.
sqlOrdem($desempate), sqlLimite()c.nome ASC, c.id ASC e LIMIT 20 OFFSET 40 — seguros para concatenar. Use um desempate único (id) para a paginação não repetir nem pular linhas.
texto($nome, $max), like($nome)Texto aparado, espaços colapsados, limitado; like com % e _ escapados. Vazio → null.
inteiro($nome, $min, $max), opcao($nome, $permitidas), opcoes($nome, $permitidas), data($nome), booleano($nome)Valor validado ou null/[]. Valores fora da lista são descartados.
resposta($itens, $total){ data, meta: { current_page, last_page, per_page, total, from, to } } — lido pelo x-lista sem configuração.
limiteMaisUm() + respostaSemTotal($linhas)Tabelas enormes sem COUNT(*): busque uma linha a mais; a sobra indica que há próxima página.
ordenarArray($linhas), paginarArray($linhas)Para dados já em memória (planilha, API externa, cache).

Opções: ordenaveis, ordem, direcao, por_pagina, por_pagina_max, pagina_max, param_pagina, param_por_pagina, param_ordem, param_direcao. Opção desconhecida, ordem padrão fora da lista branca ou coluna com caracteres estranhos lançam InvalidArgumentException — erro de programação aparece na hora, não em produção.

Joomla 3 (PHP 7.0)

Controller — task=clientes.listar
require_once JPATH_COMPONENT . '/lib/alpine-form.php';
use AlpineForm\Helpers\Consulta;

class LojaControllerClientes extends JControllerLegacy
{
    public function listar()
    {
        $app = JFactory::getApplication();
        $db = JFactory::getDbo();
        $c = Consulta::ler($app->input->get->getArray(), [
            'ordenaveis' => ['nome' => 'a.nome', 'cadastro' => 'a.created'],
            'ordem' => 'nome',
        ]);

        $q = $db->getQuery(true)->from('#__loja_clientes AS a')->where('a.state = 1');
        if ($busca = $c->like('busca')) {
            $q->where('a.nome LIKE ' . $db->quote('%' . $busca . '%'));
        }
        if ($uf = $c->opcao('uf', ['SP', 'RJ', 'MG'])) {
            $q->where('a.uf = ' . $db->quote($uf));
        }

        $total = (int) $db->setQuery((clone $q)->select('COUNT(*)'))->loadResult();
        $q->select('a.id, a.nome, a.uf')->order($c->sqlOrdem('a.id'));
        $itens = $db->setQuery($q, $c->offset(), $c->porPagina())->loadAssocList();

        $app->setHeader('Content-Type', 'application/json; charset=utf-8', true);
        $app->sendHeaders();
        echo json_encode($c->resposta($itens, $total), JSON_UNESCAPED_UNICODE);
        $app->close();
    }
}

No Joomla, deixe o token do JHtml::_('form.token') e o JResponseJson nos cadastros (Backend); Validador funciona do mesmo jeito com $app->input->get('jform', [], 'array').

Laravel

No Laravel, prefira $request->validate() e paginate() (o x-lista já lê o formato). Consulta continua útil para a lista branca de ordenação: $c = Consulta::ler($request->query(), [...]); $query->orderBy($c->coluna(), $c->direcao())->paginate($c->porPagina()).

CSRF (PHP puro)

// no layout (a sessão é iniciada se ainda não estiver)
<meta name="csrf-token" content="<?= htmlspecialchars(Csrf::token()) ?>">

// no endpoint
if (!Csrf::valido()) {
    Resposta::enviar(Resposta::erro('Sessão expirada. Recarregue a página.', 419));
}

O AlpineForm envia o token no cabeçalho X-CSRF-TOKEN (só para a mesma origem). Csrf::valido() também aceita o campo _token, para formulários que funcionam sem JavaScript. A comparação usa hash_equals.

Compatibilidade e testes

  • PHP 7.0 a 8.5, sem extensões obrigatórias (usa mbstring quando existe). Sem declare(strict_types), para conviver com código legado.
  • Testes: php php/tests/run.php (também em npm run test:php), executados em PHP 7.1, 7.4, 8.4 e 8.5.
  • A listagem de demonstração (/api/demo/clientes, usada em examples/lista.php e nos testes E2E) usa Consulta.
