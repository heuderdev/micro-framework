Validação remota

Perguntar ao servidor se um valor é aceito (e-mail já cadastrado, usuário disponível, cupom válido) enquanto a pessoa preenche.

Uso básico

<input name="email" type="email" data-form-v="required|email"
       data-form-remote="/api/validar-email"
       data-form-msg.remote="Este e-mail já está cadastrado.">
validar-email.php
<?php
header('Content-Type: application/json; charset=utf-8');
$email = strtolower(trim($_POST['email'] ?? ''));

$existe = in_array($email, ['admin@exemplo.com', 'teste@exemplo.com'], true);   // consulte o banco

echo json_encode(['valid' => !$existe, 'message' => $existe ? 'Este e-mail já está cadastrado.' : null]);
  1. As regras locais rodam primeiro. Só se passarem o servidor é consultado.
  2. Enquanto espera, o campo mostra "Verificando..." e $form.fields.email.remote vale pending.
  3. Se a pessoa digita de novo, a consulta anterior é cancelada; uma resposta antiga nunca é aplicada a um valor novo.
  4. Resposta {"valid": false} mostra a mensagem: data-form-msg.remote do campo, senão a message do servidor, senão "Este valor não está disponível.".

O que é enviado e o que se espera

Envio (POST, application/x-www-form-urlencoded)Resposta esperada (JSON)
email=ana@ex.com&_field=email + campos de data-form-remote-fields{"valid": true} ou {"valid": false, "message": "…"} (aceita mensagem)

O cabeçalho CSRF vai junto quando a URL é da mesma origem.

Opções

AtributoPadrãoEfeito
data-form-remote—URL consultada.
data-form-remote-methodpostget coloca os dados na URL.
data-form-remote-paramo nameNome do parâmetro com o valor.
data-form-remote-fields—Outros campos enviados junto, separados por vírgula. Mudar um deles revalida.
data-form-remote-debounce400 msEspera extra antes de consultar durante a digitação.
data-form-remote-timeout8 sTempo máximo da consulta.
data-form-remote-cache / -cache-ttl20 / 60 sRespostas guardadas para não repetir a consulta (0 desliga).
data-form-remote-inconclusiveallowO que fazer se o servidor não responder: allow deixa enviar, block mostra erro.
data-form-remote-adapterdefaultLê respostas em outro formato (abaixo).
data-form-remote-allow-query—Autoriza GET em campo sensível (senha).

Edição: ignorar o próprio registro

<input type="hidden" name="id" value="7">
<input name="email" type="email" value="joao@exemplo.com" data-form-v="required|email"
       data-form-remote="/api/validar-email" data-form-remote-fields="id">
$id = (int) ($_POST['id'] ?? 0);
$existe = $db->fetchOne('SELECT 1 FROM clientes WHERE email = ? AND id <> ?', [$email, $id]);

Consulta por GET

<input name="usuario" data-form-v="required|alphanumeric|min:4"
       data-form-remote="/api/usuario-disponivel" data-form-remote-method="get"
       data-form-remote-param="u">
<!-- GET /api/usuario-disponivel?u=joao&_field=usuario -->

Servidor fora do ar (inconclusivo)

Erro de rede, tempo esgotado, HTTP fora de 2xx ou resposta fora do contrato não dizem "válido" nem "inválido": o resultado é inconclusivo. A consulta é repetida uma vez em erros de rede e em 408/429/5xx.

<!-- allow (padrão): sem erro, aviso "Não foi possível verificar agora. O valor será conferido no envio." -->
<input name="email" data-form-v="email" data-form-remote="/api/validar-email">

<!-- block: erro "Não foi possível verificar este valor agora." até conseguir consultar -->
<input name="cupom" data-form-v="required" data-form-remote="/api/cupom" data-form-remote-inconclusive="block">

Resposta em outro formato

// sua API responde { "disponivel": true } ou { "disponivel": false, "motivo": "…" }
AlpineForm.remoteAdapter('disponibilidade', json => ({
    valid: json.disponivel === true,
    message: json.motivo,
}))
<input name="usuario" data-form-v="required" data-form-remote="/api/usuario" data-form-remote-adapter="disponibilidade">

Cache

Só respostas definitivas (valid verdadeiro ou falso) entram no cache. Quando o servidor devolve erro para o campo no envio, a entrada daquele valor é descartada. Para limpar manualmente:

<button type="button" @click="$form.clearRemoteCache('email')">Verificar de novo</button>

A validação remota não substitui a validação no envio: entre a consulta e o envio, outra pessoa pode ter cadastrado o mesmo e-mail. O servidor sempre confere de novo (por exemplo, com índice único no banco).
