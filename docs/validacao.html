Validação

Quando validar, como escrever regras, personalizar mensagens, escolher onde o erro aparece e controlar resumo, foco e rolagem.

Sintaxe de data-form-v

<input name="apelido" data-form-v="required|min:3|max:20|alphanumeric">
  • | separa regras; : separa o nome dos parâmetros; , separa parâmetros.
  • Espaços em volta são ignorados: required | min: 3 funciona.
  • Para usar |, :, , ou \ dentro de um parâmetro, escape com \: in:a\,b,c aceita "a,b" e "c".
  • Regras rodam na ordem escrita. As de presença (required, required_if…) rodam primeiro; se o campo está vazio e não é obrigatório, as demais não rodam.

Todas as regras: Regras.

Quando validar (modos)

data-form-validationComportamento
live (padrão)Valida ao sair do campo; depois disso, revalida durante a digitação (com debounce). Selects, radios e checkboxes validam ao mudar.
inputValida desde a primeira tecla (com debounce).
blurSó ao sair do campo. Um campo já validado volta a ser revalidado ao digitar.
changeNo evento change (ao sair de um campo de texto alterado, ou ao mudar uma escolha).
submitSó no envio. Depois da primeira tentativa, os campos já validados são revalidados ao digitar.
Modos por formulário, grupo e campo
<form x-data x-form action="/salvar" method="post" data-form-validation="blur" novalidate>
    <input name="nome" data-form-v="required">                                 <!-- blur (do form) -->
    <div data-form-validation="submit">
        <textarea name="obs" data-form-v="max:500"></textarea>                 <!-- submit (do grupo) -->
    </div>
    <input name="senha" type="password" data-form-v="required|min:8"
           data-form-validation="input">                                       <!-- input (do campo) -->
</form>

Debounce

Espera entre a última tecla e a validação. Padrão 200 ms. Aceita 300, 300ms, 1s. Também herdável por grupo e campo.

<form x-data x-form data-form-debounce="400" ...>
<input name="cnpj" data-form-v="required|cnpj" data-form-debounce="0">

Mensagens

Ordem de preferência para escolher a mensagem de um erro:

  1. data-form-msg.<regra> no campo;
  2. data-form-msg no campo (uma mensagem para qualquer regra);
  3. mensagens configuradas em AlpineForm.configure({ messages }) ou x-form="{ messages }";
  4. mensagem padrão da biblioteca (AlpineForm.messages).
Por regra e genérica
<input name="email" type="email" data-form-v="required|email"
       data-form-msg.required="Precisamos do seu e-mail."
       data-form-msg.email="Esse e-mail não parece válido.">

<input name="codigo" data-form-v="required|digits:6"
       data-form-msg="Digite os 6 números do código.">
Para todos os formulários
AlpineForm.configure({
    messages: {
        required: 'Preencha :field.',
        email: 'E-mail inválido.',
        'min.numeric': ':field deve ser no mínimo :min.',   // variante: números
    },
})

// ou alterando o padrão diretamente
AlpineForm.messages.cpf = 'CPF inválido. Confira os números.'

Placeholders

PlaceholderValor
:fieldNome do campo (ver rótulo abaixo).
:valueValor digitado (vazio em senhas e campos sensíveis; cortado em 60 caracteres).
:min, :max, :length, :step…Parâmetros da regra, pelo nome.
:otherRótulo do outro campo (same, required_with, datas comparadas).
:allowedLista permitida (in, ext, mime…).
:fileNome do arquivo (regras de arquivo).

Rótulo (:field)

Vem de data-form-label; se não houver, do <label for> ou <label> que envolve o campo; por último, do name.

<label for="nasc">Data de nascimento</label>
<input id="nasc" name="nasc" type="date" data-form-v="required">
<!-- "O campo Data de nascimento é obrigatório." -->

<input name="cpf_resp" data-form-v="required|cpf" data-form-label="CPF do responsável">
<!-- "O campo CPF do responsável é obrigatório." -->

Mensagens são sempre inseridas como texto: HTML em mensagens (inclusive as do servidor) aparece literalmente, nunca é interpretado.

Um erro ou todos

<form x-data x-form data-form-errors="all" ...>          <!-- mostra todos os erros de cada campo -->
<input name="senha" type="password" data-form-v="min:8|pattern" data-form-pattern="[0-9]"
       data-form-errors="first">                          <!-- só o primeiro neste campo -->

Padrão: first. Regras assíncronas e a validação remota só rodam se as síncronas passaram.

Marcar campos válidos

Com data-form-show-valid, campos validados e corretos recebem a classe af-valid (is-valid no Bootstrap). Campos ainda não validados nunca aparecem como aprovados.

<form x-data x-form data-form-show-valid ...>

Onde o erro aparece

Por padrão, um elemento <div class="af-error"> é criado logo depois do campo (ou do <label> que envolve o campo). Em grupos de radios/checkboxes dentro de um <fieldset>, ele vai para o final do fieldset. Para escolher outro lugar:

<div class="linha">
    <input name="ddd" data-form-v="required|digits:2" data-form-error-target="#erro-telefone">
    <input name="numero" data-form-v="required|digits" data-form-error-target="#erro-telefone">
</div>
<div id="erro-telefone"></div>

Ou exiba você mesmo com Alpine, sem depender do elemento gerado:

<input name="email" data-form-v="required|email">
<small class="erro" x-show="$form.hasError('email')" x-text="$form.firstError('email')"></small>

Resumo de erros

data-form-summaryO que lista
general (padrão)Só erros sem campo visível: erros gerais do servidor, de rede, campos hidden.
allTodos os erros, cada um com botão que leva ao campo.
noneNenhum resumo (mostre $form.generalErrors você mesmo).
Posição do resumo
<form x-data x-form data-form-summary="all" ...>
    <div data-form-errors-summary></div>   <!-- o resumo é colocado aqui -->
    ...
</form>

<!-- ou fora do form -->
<form id="pedido" x-data x-form data-form-summary-target="#erros-pedido" ...></form>
<div id="erros-pedido"></div>

Sem contêiner, o resumo é criado no início do form. Ele recebe role="alert" e título "Corrija os itens abaixo:".

Foco e rolagem

No envio inválido, o primeiro campo com erro (na ordem da página) recebe foco e é rolado até o centro da tela, com rolagem suave (instantânea se o sistema pede menos movimento).

<form x-data x-form data-form-focus="none" ...>     <!-- não foca -->
<form x-data x-form data-form-scroll="instant" ...> <!-- smooth (padrão) | instant | none -->

Campo dentro de aba, accordion ou modal fechado? Use o hook reveal para abrir antes do foco (exemplo).

Validar pelo código

<button type="button" @click="$form.validate().then(r => console.log(r.valid, r.errors))">Conferir</button>
<button type="button" @click="$form.validateField('email')">Conferir e-mail</button>
<button type="button" @click="$form.resetValidation()">Limpar erros</button>

validate() devolve { valid, errors, invalidFields }, mostra os erros nos campos, mas não envia nem move o foco.
