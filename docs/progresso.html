Progresso e cancelamento

Barra de progresso com bytes reais, velocidade, tempo restante, texto de status, botão cancelar e tempo limite — sem nenhuma animação falsa.

Barra de progresso

Com elemento progress
<div data-form-progress>
    <progress data-form-progress-bar max="100" aria-label="Progresso do envio"></progress>
    <span data-form-progress-percent></span>
    <p data-form-status></p>
</div>
Com div (estilizável)
<div data-form-progress class="caixa-progresso">
    <div class="trilho"><div class="preenchimento" data-form-progress-bar aria-label="Enviado"></div></div>
    <p>
        <span data-form-progress-percent></span>
        (<span data-form-progress-loaded></span> de <span data-form-progress-total></span>)
        · <span data-form-progress-speed></span>
        · restam <span data-form-progress-eta></span>
        · <span data-form-progress-elapsed></span>
    </p>
    <p data-form-status></p>
</div>
AtributoRecebe
data-form-progressContêiner: atributos data-form-state (a fase) e aria-busy. Com o CSS opcional, fica oculto em idle.
data-form-progress-bar<progress>: value. Outro elemento: style.width em %, role="progressbar", aria-valuenow/aria-valuetext. data-indeterminate="true" quando não há total.
data-form-progress-percent42%
data-form-progress-loaded / -total3,4 MB / 8,1 MB
data-form-progress-speed1,2 MB/s (média dos últimos 3 s)
data-form-progress-etatempo restante estimado (aparece após 1 s)
data-form-progress-elapsedtempo decorrido
data-form-statustexto da fase; recebe role="status" e aria-live="polite" para leitores de tela
Com Alpine, do seu jeito
<div x-show="$form.uploading || $form.awaitingResponse">
    <div class="trilho"><div class="preenchimento" :style="`width: ${$form.progress.percent ?? 0}%`"></div></div>
    <small x-text="$form.awaitingResponse ? 'Processando no servidor…' : ($form.progress.percent ?? 0) + '%'"></small>
</div>

AlpineForm.configure({ messages: { 'status.awaiting': 'Recebido! Estamos salvando seus arquivos…' } })

Como é medido

  • Os números vêm dos eventos reais do navegador durante o envio (XMLHttpRequest). Nada é simulado.
  • Em multipart, os bytes são do corpo HTTP inteiro (inclui os separadores do multipart), então o total é um pouco maior que a soma dos arquivos.
  • 100% = tudo saiu do navegador. Daí em diante a fase é awaiting até a resposta chegar.
  • Velocidade e tempo restante são estimativas e oscilam com a rede.
  • Com data-form-transport="fetch" não existe progresso de upload: a barra fica indeterminada.
  • Em localhost o envio é quase instantâneo; para ver a barra andar, use o DevTools (Network → Throttling).

Por arquivo, num único envio, não há como medir; para isso use o upload em partes.

Cancelar

<button type="button" data-form-cancel>Cancelar</button>
<!-- ou -->
<button type="button" x-show="$form.submitting" @click="$form.cancel()">Cancelar</button>

[data-form-cancel] fica desabilitado quando não há o que cancelar. Cancelar interrompe a requisição, leva à fase canceled ("Envio cancelado.") e dispara form:cancel; não é tratado como erro do formulário.

Cancelar depois que o upload chegou a 100% interrompe a espera, mas o servidor pode já ter recebido e gravado. Em processamento posterior (202), cancelar só para de acompanhar — veja Processamento.

Tempo limite

<form x-data x-form action="/api/importar" method="post" data-form-timeout="2min" novalidate>
Quando o tempo acaba$form.error.kindMensagem
Ainda enviandotimeoutO servidor demorou demais para responder.
Já enviou tudo, esperando respostaunknownA conexão caiu depois do envio. Não é possível confirmar se a operação foi concluída; verifique antes de enviar novamente.

No segundo caso o servidor pode ter concluído; por isso nada é reenviado automaticamente. Use idempotência se reenvios duplicados forem um problema.

Eventos de progresso

<form x-data="{ pct: 0 }" x-form action="/api/upload" method="post"
      @form:progress="pct = $event.detail.percent ?? 0"
      @form:uploaded="console.log('Upload concluído, aguardando resposta')" novalidate>

$event.detail de form:progress: { loaded, total, percent, indeterminate, lengthComputable, speed, eta, elapsed, uploaded, phase }.

CSS útil

<style>
    .trilho { height: 8px; background: #e5e7eb; border-radius: 4px; overflow: hidden; }
    .preenchimento { height: 100%; width: 0; background: #2563eb; transition: width .2s; }
    form[data-form-state="awaiting"] .preenchimento { background: #16a34a; }
</style>

O CSS opcional (alpine-form.css) já anima a barra indeterminada (respeitando "reduzir movimento") e esconde [data-form-progress] quando parado.
