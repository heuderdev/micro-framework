titulo: Avisos e confirmação lead: Avisos flutuantes (toasts) depois do envio e uma confirmação acessível antes de enviar ou excluir — com atributos, sem escrever modal. Requer alpine-form-avisos e o CSS opcional. ---

Instalação

@@@html @@@ @@@js ESM import avisos from 'alpine-form/avisos' AlpineForm.use(avisos) @@@

Exemplo executável: examples/avisos.php.

Aviso depois do envio (data-form-avisos)

@@@html
@@@
ValorMostra
data-form-avisosSucesso e erro.
data-form-avisos="sucesso"Só o sucesso (erros ficam no resumo/campos).
data-form-avisos="erro"Só erros.
  • Sucesso: texto de data-form-aviso-sucesso, senão o message do servidor, senão "Salvo com sucesso.".
  • Erro: a mensagem do erro (rede, 500, 403, 422 "Confira os campos destacados"...). Erro de validação no navegador não gera aviso — os campos já mostram.
  • Combina com data-form-reset-on-success e data-form-lista: salvar, limpar, avisar e atualizar a tabela.

Confirmação antes de enviar (data-form-confirmar)

@@@html No formulário
...
@@@ @@@html Num botão (só ele pergunta)
@@@
  1. Clicou: o formulário é validado primeiro. Inválido não pergunta (mostra os erros).
  2. Válido: abre um <dialog> modal com o texto, "Cancelar" e o botão de confirmação.
  3. Cancelar, Esc ou fechar: nada é enviado (o envio termina como cancelado). Confirmar: envia normalmente, com o botão que foi clicado (acao=excluir).
  4. O foco fica preso no diálogo e volta ao botão de origem ao fechar. Com data-form-confirmar-perigo, o foco começa em "Cancelar" (Enter por engano não exclui) e o botão fica vermelho.
Atributo (form ou botão submit)Efeito
data-form-confirmar="texto"Pergunta antes de enviar. No botão, vale só para ele (tem precedência sobre o do form).
data-form-confirmar-tituloTítulo do diálogo.
data-form-confirmar-okTexto do botão de confirmação (padrão "Confirmar").
data-form-confirmar-perigoAção destrutiva: foco em Cancelar e estilo de perigo.

Não funciona com data-form-transport="native" (o navegador envia sem passar pelo AlpineForm). A confirmação é uma ajuda para a pessoa, não uma proteção: o servidor continua conferindo permissão e regras.

Pelo código ($avisos e $confirmar)

@@@html
@@@ @@@js AlpineForm.avisos.sucesso('Salvo.') // também: erro, aviso, info const id = AlpineForm.avisos.mostrar('Processando…', { tipo: 'info', duracao: 0 }) AlpineForm.avisos.fechar(id) AlpineForm.avisos.limpar() if (await AlpineForm.avisos.confirmar('Sair sem salvar?', { titulo: 'Alterações não salvas', confirmar: 'Sair', cancelar: 'Continuar editando' })) { location.href = '/pedidos' } // em outro componente: avisar quando a lista falhar document.addEventListener('lista:erro', e => AlpineForm.avisos.erro(e.detail.erro.message)) @@@

Comportamento e acessibilidade

  • Duração: sucesso e info 5 s, aviso 7 s, erro 8 s; duracao: 0 só fecha no ×. No máximo 4 na tela (o mais antigo sai).
  • Não some enquanto o mouse está em cima ou o foco está nele (dá tempo de ler).
  • Ficam em regiões vivas: role="status" (educado) e, para erros, role="alert" — leitores de tela anunciam sem roubar o foco.
  • Texto sempre como texto (textContent): mensagem do servidor com HTML aparece literalmente. Quebras de linha são preservadas.
  • Uma confirmação por vez: uma segunda chamada enquanto o diálogo está aberto resolve false.
  • Sem showModal (navegadores muito antigos), o diálogo abre com open e o módulo mantém o foco entre os botões.
  • Tudo que é criado tem data-form-generated e classes af-avisos, af-aviso, af-aviso--sucesso|erro|aviso|info, af-confirmar, af-confirmar--perigo — personalize no seu CSS.
  • Textos padrão em AlpineForm.messages: avisos.sucesso, avisos.erro, avisos.confirmar, avisos.cancelar, avisos.confirmar_envio, avisos.fechar.

Referência

Atributos no form: data-form-avisos ("" | sucesso | erro), data-form-aviso-sucesso, data-form-confirmar e variantes. No botão submit: data-form-confirmar, -titulo, -ok, -perigo.

API: AlpineForm.avisos.mostrar(texto, { tipo, duracao }) (devolve o id), sucesso, erro, aviso, info, fechar(id), limpar(), confirmar(texto, { titulo, confirmar, cancelar, perigo }) → Promise<boolean>. No Alpine: $avisos e $confirmar(texto, opções). Evento no document: avisos:mostrado ({ id, tipo, texto }).
