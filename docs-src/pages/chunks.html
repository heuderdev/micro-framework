titulo: Upload em partes lead: Arquivos grandes enviados em partes, com várias partes ao mesmo tempo, nova tentativa automática, pausa, retomada (inclusive após recarregar a página) e verificação de integridade. Requer alpine-form-chunks e um backend que implemente o protocolo. ---

Quando usar

  • Arquivos maiores que o limite do servidor (post_max_size, proxy).
  • Conexões instáveis: uma falha repete só a parte, não o arquivo inteiro.
  • Precisa de pausar/retomar ou de progresso por arquivo.

O arquivo é enviado antes do formulário, para um endpoint próprio. Ao terminar, o servidor devolve um token; o formulário é então enviado com o token no lugar do arquivo.

O que acontece

POST /api/uploadscria a sessão → uploadId
↓
PUT /api/uploads/{id}/parts/{n}partes em paralelo, com nova tentativa em falha
↓
POST /api/uploads/{id}/completeservidor monta o arquivo → token
↓
POST /api/documentosformulário com arquivo=<token>; o servidor vincula o arquivo ao registro

O progresso conta só partes confirmadas + bytes em voo: uma parte repetida não é contada duas vezes. Fases: uploading (partes) → uploading/awaiting (formulário) → success.

Pausar e retomar

  • Pausar interrompe as partes em voo (os bytes delas deixam de contar) e não inicia novas. Fase paused.
  • Retomar pergunta ao servidor quais partes ele já tem e envia só as que faltam.
  • Pelo código: $form.pauseUpload(), $form.resumeUpload() (com nome do campo para um só).
  • Os botões data-form-pause/data-form-resume se habilitam sozinhos conforme o estado.

Retomar depois de recarregar

Com data-form-chunk-persist, só os dados da sessão (id, nome, tamanho, data) ficam no localStorage. O navegador não guarda o arquivo: a pessoa precisa selecionar o mesmo arquivo de novo e enviar; ele é reconhecido (nome, tamanho, data e amostras do conteúdo) e só as partes que faltam são enviadas.

$form.uploads.<campo>: { status, files: [...], resumable }, com status em idle, uploading, paused, completed, failed. Cada arquivo: { name, size, uploadId, status, totalParts, receivedParts, loaded, resumed, error } (também em $form.getUploadSession('arquivo')).

Falhas

SituaçãoReação
Rede, 408, 429, 5xx numa parteRepete a parte com espera crescente (respeita Retry-After).
409 (parte já existe com conteúdo diferente)Falha sem repetir.
404/410 (sessão expirou)Cria nova sessão uma vez e recomeça.
Erro ao finalizarStatus failed; enviar de novo tenta outra vez.
CancelarInterrompe e pede ao servidor para apagar a sessão (DELETE).

Mensagem de falha: "Falha ao enviar o arquivo :file." seguida do motivo.

Protocolo do servidor

RequisiçãoResposta
POST {endpoint} JSON {name, size, type, lastModified, chunkSize, fingerprint}201 {uploadId, chunkSize, totalParts, expiresAt, receivedParts: []}
GET {endpoint}/{id}{uploadId, size, chunkSize, totalParts, receivedParts, status, expiresAt}
PUT {endpoint}/{id}/parts/{n} corpo = bytes; cabeçalhos X-Chunk-Offset, X-Chunk-Size, X-Chunk-Sha256200 {received} · 409 · 404/410
POST {endpoint}/{id}/complete JSON {manifest}{status: "completed", token, size}
DELETE {endpoint}/{id}204

Uma implementação completa em PHP está em server/src/ChunkStore.php (gravação atômica das partes, verificação de hash, montagem sob trava, tokens por dono, limpeza por server/bin/cleanup.php). Veja Backend › Upload em partes.

"Upload concluído" ainda não é "registro salvo": o endpoint do formulário precisa validar o token (pertence ao usuário? ainda não foi usado?) e vincular o arquivo.
