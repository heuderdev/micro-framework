Como é medido

  • Os números vêm dos eventos reais do navegador durante o envio (XMLHttpRequest). Nada é simulado.
  • Em multipart, os bytes são do corpo HTTP inteiro (inclui os separadores do multipart), então o total é um pouco maior que a soma dos arquivos.
  • 100% = tudo saiu do navegador. Daí em diante a fase é awaiting até a resposta chegar.
  • Velocidade e tempo restante são estimativas e oscilam com a rede.
  • Com data-form-transport="fetch" não existe progresso de upload: a barra fica indeterminada.
  • Em localhost o envio é quase instantâneo; para ver a barra andar, use o DevTools (Network → Throttling).

Por arquivo, num único envio, não há como medir; para isso use o upload em partes.

Cancelar

@@@html @@@

[data-form-cancel] fica desabilitado quando não há o que cancelar. Cancelar interrompe a requisição, leva à fase canceled ("Envio cancelado.") e dispara form:cancel; não é tratado como erro do formulário.

Cancelar depois que o upload chegou a 100% interrompe a espera, mas o servidor pode já ter recebido e gravado. Em processamento posterior (202), cancelar só para de acompanhar — veja Processamento.
