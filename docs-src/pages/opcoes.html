titulo: Selects dependentes lead: Opções de um select vindas da API e que dependem de outros campos — UF → cidade → bairro, categoria → produto, empresa → filial — só com atributos. Requer alpine-form-opcoes. ---

Instalação

@@@html @@@ @@@js ESM import opcoes from 'alpine-form/opcoes' AlpineForm.use(opcoes) @@@

Exemplo executável: examples/opcoes.php.

UF → cidade → bairro

@@@html
@@@
  1. Ao abrir, uf busca /api/ufs (não depende de ninguém).
  2. {uf} é trocado pelo valor do campo uf. Enquanto ele estiver vazio, cidade fica sem opções e desabilitado (campo desabilitado não valida nem é enviado).
  3. Escolheu a UF: cidade busca /api/cidades?uf=SP. Trocou a UF: a lista antiga some na hora, a requisição anterior é cancelada e a resposta antiga nunca sobrescreve a nova.
  4. Se o valor escolhido não existe na lista nova, o campo é limpo — e isso limpa o bairro. A cadeia se propaga sozinha.
  5. A <option value=""> escrita no HTML é o placeholder: fica sempre.

O que o servidor responde

FormatoExemplo
Lista de objetos[{ "id": 3550308, "nome": "São Paulo" }, …]
Laravel / Resource{ "data": [{ "id": 1, "name": "…" }] }
Contrato AlpineForm / Joomla{ "success": true, "data": [...] } ou { "success": true, "data": { "opcoes": [...] } } (também itens, items, options)
Mapa valor → texto{ "SP": "São Paulo", "RJ": "Rio de Janeiro" }
Lista de textos["Sé", "Mooca", "Pinheiros"] (valor = texto)

Em objetos, o valor é lido de value, id, codigo, sigla ou key; o texto, de label, text, nome, name, descricao ou titulo. Para outros nomes:

@@@html @@@ @@@php PHP puro prepare('SELECT id, nome FROM cidades WHERE uf = ? ORDER BY nome'); $st->execute([$uf]); header('Content-Type: application/json; charset=utf-8'); echo json_encode($st->fetchAll(PDO::FETCH_ASSOC), JSON_UNESCAPED_UNICODE); @@@ @@@php Laravel Route::get('/api/cidades', fn (Request $r) => Cidade::where('uf', $r->validate(['uf' => 'required|size:2'])['uf'])->orderBy('nome')->get(['id', 'nome']) ); @@@

O usuário pode chamar o endpoint com qualquer parâmetro e enviar qualquer valor no formulário. No salvamento, confira de novo que a cidade pertence à UF (Validador::em() nos Helpers PHP, Rule::exists no Laravel).

Formulário de edição (valores já salvos)

@@@html @@@

O valor inicial é o de data-form-opcoes-selecionado ou o da <option selected> que o servidor renderizou. As listas carregam em cadeia e cada valor é selecionado quando a sua lista chega. As opções estáticas com valor são substituídas pela lista da API na primeira carga.

Outras dependências

  • Vários campos: data-form-opcoes="/api/turmas?curso={curso}&turno={turno}" — só busca quando todos estiverem preenchidos.
  • Campo de texto (código, CEP): espera a digitação parar (data-form-opcoes-debounce, padrão 250 ms). Selects, radios e checkboxes buscam na hora.
  • Nomes com colchetes: {endereco[uf]} ou {endereco.uf}.
  • Campo com máscara: vai o valor de envio — o mesmo que o servidor recebe no submit (veja data-form-submit-value em Máscaras).
  • Sem dependência: data-form-opcoes="/api/bancos" só carrega a lista uma vez ao abrir.

Cada linha tem a sua cadeia. Linhas adicionadas depois são reconhecidas sozinhas; linhas removidas liberam requisições e listeners.

Grupos, lista vazia e select múltiplo

@@@html @@@
  • data-form-opcoes-grupo="regiao" agrupa em <optgroup> pelo campo indicado.
  • data-form-opcoes-vazio: texto de uma opção desabilitada quando a API devolve lista vazia (o select também fica desabilitado).
  • Select múltiplo mantém os valores que continuam existindo na nova lista.

Carregando e erro

@@@css select[data-form-opcoes-estado="carregando"] { cursor: progress; opacity: .7; } /* já em alpine-form.css */ select[data-form-opcoes-estado="erro"] { border-color: #b91c1c; } @@@ @@@html

Não foi possível carregar as opções.

@@@
  • data-form-opcoes-estado: aguardando (falta dependência), carregando, pronto ou erro. Durante a carga o select tem aria-busy="true".
  • Em erro (rede, HTTP, resposta que não é JSON ou formato desconhecido) o select volta a ficar habilitado, sem opções; o erro vai ao console (respeita data-form-log="none").
  • Eventos no form: form:opcoes-carregadas ({ name, total, url }) e form:opcoes-erro ({ name, url, status }).
  • Um select desabilitado pelo seu HTML ou pelo Alpine nunca é reabilitado pelo módulo. Para não desabilitar enquanto espera: data-form-opcoes-manter-habilitado.

Cache

As listas ficam na memória da página por URL (até 100): voltar para uma UF já escolhida não repete a requisição, e vários selects com a mesma URL compartilham a resposta. Nada é gravado em localStorage. Desligue com data-form-opcoes-cache="false" (dados que mudam a todo momento) ou force: AlpineForm.opcoes.recarregar(form, 'cidade'); AlpineForm.opcoes.limparCache() esvazia tudo.

Erros de configuração bloqueiam o envio e aparecem no console: {campo} inexistente, URL de outra origem (use um endpoint do próprio site como proxy), atributo fora de <select>, duração inválida, select que depende dele mesmo.
