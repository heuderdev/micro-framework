Campo e chave

Todo input, select e textarea com name dentro do form vira um campo. Radios e checkboxes com o mesmo nome formam um único campo (o valor de um grupo de checkboxes é uma lista).

Cada campo tem uma chave com pontos, usada em $form.errors e $form.fields:

name no HTMLChave
emailemail
itens[0][nome]itens.0.nome
jform[title]jform.title
documentos[]documentos

Nos métodos ($form.getValue('itens[0][nome]')) você pode usar qualquer uma das duas formas.

Configuração em camadas

Do mais fraco para o mais forte:

  1. Padrão da biblioteca.
  2. AlpineForm.configure({ … }) — vale para todos os formulários da página.
  3. x-form="{ … }" — objeto no próprio form.
  4. Atributos data-form-* no <form>.
  5. Para opções de campo (modo de validação, debounce, erros, ocultos…): atributo num elemento acima do campo dentro do form (um <fieldset>, uma <div>) e, por fim, no próprio campo.

Nada é ignorado em silêncio

Um atributo data-form-* desconhecido, uma regra escrita errado (requried), um parâmetro inválido (min:abc) ou um módulo não carregado viram erro de configuração:

  • o campo mostra "Este campo tem uma configuração inválida e não pode ser validado.";
  • o console mostra o motivo exato (e sugere a regra certa: "Você quis dizer "required"?");
  • o envio é bloqueado — um formulário mal configurado nunca é enviado "sem validar".

Quando o erro aparece

No modo padrão (live), o erro de um campo só aparece depois que a pessoa sai do campo pela primeira vez ou tenta enviar. A partir daí, o campo é revalidado enquanto ela digita. Selects, radios e checkboxes validam ao mudar. Outros modos em Validação.

Fases do envio

$form.phase diz em que ponto o envio está. O atributo data-form-state do form recebe o mesmo valor (útil para CSS).

FaseSignificadoAtalho booleano
idleParado.—
validatingValidando todos os campos antes de enviar.submitting
uploadingEnviando os bytes.submitting, uploading
pausedUpload em partes pausado.submitting, uploading, paused
awaitingTudo enviado; esperando a resposta do servidor.submitting, awaitingResponse
processingServidor aceitou (202) e está processando; a biblioteca acompanha.submitting, processing
successConcluído com sucesso.success
errorFalhou (validação do servidor, rede, HTTP…).failed
canceledCancelado pelo usuário.canceled
100% não é concluído

Quando a barra chega a 100%, o arquivo saiu do navegador, mas o servidor ainda vai gravar e responder (e pode recusar). Por isso existe a fase awaiting ("Envio concluído. Aguardando resposta do servidor…"). Só success significa que deu certo.

Estado de cada campo

$form.fields['email'] (ou $form.field('email')):

PropriedadeSignificado

filledTem valor.
touchedA pessoa já saiu do campo (ou mudou a escolha).
dirtyValor diferente do inicial.
validated / validatingJá tem resultado de validação / validação em andamento.
valid / invalidValidado e sem erros / com erros. Um campo nunca validado tem os dois false.

No formulário: $form.dirty, $form.pristine, $form.validating, $form.errors (só campos com erro), $form.generalErrors (erros sem campo), $form.result, $form.error, $form.progress, $form.status (texto da fase).

Representações de um valor

Com máscara ou normalizador, um mesmo campo tem várias formas:

RepresentaçãoCPFMoedaData
display (o que está no input)529.982.247-25R$ 1.234,5031/12/2026
raw (só o que foi digitado de significativo)5299822472512345031122026
formatted529.982.247-25R$ 1.234,5031/12/2026
canonical (para máquinas)529982247251234.502026-12-31

Você escolhe qual vai para a validação (data-form-mask-validation-value) e qual vai para o servidor (data-form-submit-value). Detalhes em Máscaras.

Formulários isolados

Cada <form x-form> tem seu próprio estado. Vários formulários na mesma página, inclusive com campos de mesmo nome, não interferem entre si.
