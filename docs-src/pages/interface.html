O que é escrito na página

OndeO quê
Campo com erroclasse af-invalid, aria-invalid="true", aria-describedby apontando para a mensagem
Campo válidoclasse af-valid (só com data-form-show-valid)
Validação remota em andamentoclasse af-pending; mensagem "Verificando..." em af-error--pending
Mensagem<div class="af-error"> com <span class="af-error__item"> por mensagem
Resumoaf-summary, af-summary__title, af-summary__list, role="alert"
Lista de arquivosaf-files, af-file, af-file--invalid, af-file__thumb, af-file__name, af-file__size, af-file__errors, af-file__remove
Arquivo existente removidoaf-existing--removed
Dropzone com arquivo sobre elaaf-dropzone--over
<form>data-form-state="<fase>"; aria-busy="true" durante o envio

Tudo que a biblioteca cria leva data-form-generated e é removido (com os atributos ARIA originais restaurados) quando o formulário é destruído.

Usar as classes do seu CSS

Registre um adaptador que estende o padrão trocando só as classes (Tailwind, Bulma, CSS próprio):

@@@js const Base = AlpineForm.internals.DefaultUiAdapter AlpineForm.uiAdapter('tailwind', ctx => new Base(ctx, { classes: { invalid: 'border-red-500 ring-1 ring-red-500', valid: 'border-green-600', error: 'mt-1 text-sm text-red-600', summary: 'rounded border border-red-300 bg-red-50 p-3 text-red-800', fileList: 'mt-2 space-y-1', fileItem: 'flex items-center gap-2', fileRemove: 'ml-auto text-sm text-red-600 underline', }, })) AlpineForm.configure({ ui: 'tailwind' }) @@@

Chaves disponíveis: invalid, valid, pending, error, errorItem, errorPending, summary, summaryTitle, summaryList, fileList, fileItem, fileItemInvalid, fileThumb, fileName, fileSize, fileErrors, fileRemove, existingRemoved, dropzoneOver. Use várias classes separadas por espaço.

AlpineForm.internals é usado pelos módulos oficiais e não tem garantia de estabilidade entre versões. Para controle total do HTML, implemente um adaptador completo (Extensões › Adaptador de UI).

Acessibilidade

  • Mensagens de campo são ligadas por aria-describedby e lidas ao focar o campo (não são anunciadas a cada tecla).
  • O resumo usa role="alert"; [data-form-status] recebe role="status" e aria-live="polite".
  • No envio inválido, o foco vai para o primeiro campo com erro; a rolagem respeita "reduzir movimento".
  • Botões de remover arquivo têm aria-label="Remover <nome>" e o foco é preservado ao redesenhar a lista.
  • Do seu lado: <label> em todo campo, <fieldset>/<legend> em grupos, aria-label nas barras de progresso e contraste adequado.
