titulo: Helpers PHP lead: Um arquivo PHP sem dependências (PHP 7.0 a 8.x, inclusive Joomla 3) que tira a repetição do backend: respostas no contrato do AlpineForm, leitura do corpo em qualquer codificação, validação com mensagens em português e parâmetros de listagem seguros para o x-lista. ---

Instalação

Copie php/alpine-form.php para o projeto (ou use direto de node_modules/alpine-form/php/alpine-form.php) e inclua:

As mesmas regras no navegador (para o usuário) e no servidor (para valer). Os erros do servidor aparecem embaixo de cada campo; o que não tiver campo vai para o resumo.

Resposta

MétodoGera
Resposta::sucesso($dados, $mensagem, $status = 200){ "success": true, "message": "…", "data": … }
Resposta::invalido($erros, $mensagem)HTTP 422 { "success": false, "message": "Confira os campos destacados.", "errors": { "campo": ["…"] } } — aceita mensagem única ou lista; chave "" ou "_" vai para o resumo geral.
Resposta::erro($mensagem, $status = 400, $dados = null)Erro sem campo (regra de negócio, 403, 409…). Não coloque detalhes internos (SQL, caminhos) na mensagem.
Resposta::aceito($jobId, $statusUrl, $cancelUrl)HTTP 202 com job — o formulário acompanha o processamento.
Resposta::enviar([$status, $corpo])Envia com Content-Type: application/json; charset=utf-8, X-Content-Type-Options: nosniff, Cache-Control: no-store e encerra (Resposta::$semExit = true para não encerrar).
Resposta::json($corpo)Só o texto JSON (acentos preservados; UTF-8 inválido não gera resposta vazia).

Os métodos devolvem [status, corpo] sem enviar nada: dá para testar, registrar ou adaptar (ex.: return response()->json($corpo, $status) no Laravel).

Validador

Encadeie as regras. Todas, exceto obrigatorio, ignoram campo vazio (campo opcional). Depois do primeiro erro de um campo, as demais regras desse campo não acrescentam mensagens — o usuário vê um problema por vez, como no navegador.

RegraEquivalente no HTMLMensagem padrão
obrigatorio($campo)requiredPreencha este campo.
tamanho($campo, $min, $max)min:3|max:80Use pelo menos :min / no máximo :max caracteres. (conta caracteres, não bytes)
email, cpf, cnpj, cpfOuCnpj, cep, telefone, urlemail, cpf, cnpj, cpf_cnpj…Informe um e-mail válido. / CPF inválido. … (url só aceita http e https)
inteiro($campo, $min, $max)integerInforme um número inteiro.
decimal($campo, $casas, $min, $max)decimal:2 (máscara moeda envia "1234.50")Comparação exata em texto, nunca float: passe limites como texto ('0.01').
em($campo, $opcoes)in: / selectEscolha uma opção válida. (vale também para listas)
data($campo, $formato, $min, $max)date, after, beforeFormato padrão Y-m-d (input date); limites no mesmo formato ou 'hoje'. 30/02 é rejeitado.
igual($campo, $outro)same:senhaOs valores não conferem.
regex($campo, $padrao), regra($campo, $msg, $nome, fn)regra própriaFormato inválido.
erro($campo, $mensagem)—Erro seu (duplicidade, regra de negócio).

Toda regra aceita uma mensagem própria como último argumento: $v->obrigatorio('nome', 'Informe o nome completo.'). Para mudar o padrão de todo o sistema: Validador::$mensagens['obrigatorio'] = 'Campo obrigatório.'.

@@@php Itens de uma lista dinâmica (itens[0][produto], itens[1][produto]...) $v->cadaItem('itens', function (Validador $item, $indice) { $item->obrigatorio('produto')->inteiro('qtd', 1, 999)->decimal('preco', 2, '0.01'); }); // erros: { "itens.1.produto": ["Preencha este campo."] } → aparece no campo da linha 2 @@@

Nomes com colchetes viram ponto nos erros (jform[nome] → jform.nome), formato que o AlpineForm associa ao campo.

Consulta (listagens)

Lê page, per_page, sort, direction e os filtros do x-lista sem confiar em nada: página e tamanho com limites, ordenação só pelas colunas permitidas, filtros com tipo.

@@@php api/clientes.php (PDO) ['nome' => 'c.nome', 'cadastro' => 'c.criado_em', 'saldo' => 'c.saldo'], // parâmetro => coluna 'ordem' => 'nome', 'por_pagina' => 20, 'por_pagina_max' => 100, ]); $where = ['1 = 1']; $params = []; if ($busca = $c->like('busca')) { // % e _ digitados viram literais $where[] = "(c.nome LIKE ? ESCAPE '\\\\' OR c.email LIKE ? ESCAPE '\\\\')"; array_push($params, "%$busca%", "%$busca%"); } if ($uf = $c->opcao('uf', ['SP', 'RJ', 'MG'])) { $where[] = 'c.uf = ?'; $params[] = $uf; } if ($status = $c->opcoes('status', ['ativo', 'inativo', 'pendente'])) { $where[] = 'c.status IN (' . implode(',', array_fill(0, count($status), '?')) . ')'; $params = array_merge($params, $status); } if ($de = $c->data('de')) { $where[] = 'c.criado_em >= ?'; $params[] = $de; } $filtro = implode(' AND ', $where); $total = $pdo->prepare("SELECT COUNT(*) FROM clientes c WHERE $filtro"); $total->execute($params); $linhas = $pdo->prepare("SELECT c.id, c.nome, c.email, c.uf, c.status FROM clientes c WHERE $filtro ORDER BY {$c->sqlOrdem('c.id')} {$c->sqlLimite()}"); $linhas->execute($params); Resposta::enviar([200, $c->resposta($linhas->fetchAll(PDO::FETCH_ASSOC), (int) $total->fetchColumn())]); @@@
MétodoDevolve
pagina(), porPagina(), offset()Inteiros já limitados (página 1 a 10000; tamanho 1 a por_pagina_max).
ordem(), direcao(), coluna()Nome público aceito, asc/desc e a coluna SQL da lista branca.
sqlOrdem($desempate), sqlLimite()c.nome ASC, c.id ASC e LIMIT 20 OFFSET 40 — seguros para concatenar. Use um desempate único (id) para a paginação não repetir nem pular linhas.
texto($nome, $max), like($nome)Texto aparado, espaços colapsados, limitado; like com % e _ escapados. Vazio → null.
inteiro($nome, $min, $max), opcao($nome, $permitidas), opcoes($nome, $permitidas), data($nome), booleano($nome)Valor validado ou null/[]. Valores fora da lista são descartados.
resposta($itens, $total){ data, meta: { current_page, last_page, per_page, total, from, to } } — lido pelo x-lista sem configuração.
limiteMaisUm() + respostaSemTotal($linhas)Tabelas enormes sem COUNT(*): busque uma linha a mais; a sobra indica que há próxima página.
ordenarArray($linhas), paginarArray($linhas)Para dados já em memória (planilha, API externa, cache).

Opções: ordenaveis, ordem, direcao, por_pagina, por_pagina_max, pagina_max, param_pagina, param_por_pagina, param_ordem, param_direcao. Opção desconhecida, ordem padrão fora da lista branca ou coluna com caracteres estranhos lançam InvalidArgumentException — erro de programação aparece na hora, não em produção.

'/lib/alpine-form.php'; use AlpineForm\Helpers\Consulta; class LojaControllerClientes extends JControllerLegacy { public function listar() { $app = JFactory::getApplication(); $db = JFactory::getDbo(); $c = Consulta::ler($app->input->get->getArray(), [ 'ordenaveis' => ['nome' => 'a.nome', 'cadastro' => 'a.created'], 'ordem' => 'nome', ]); $q = $db->getQuery(true)->from('#__loja_clientes AS a')->where('a.state = 1'); if ($busca = $c->like('busca')) { $q->where('a.nome LIKE ' . $db->quote('%' . $busca . No Joomla, deixe o token do JHtml::_('form.token') e o JResponseJson nos cadastros (Backend); Validador funciona do mesmo jeito com $app->input->get('jform', [], 'array').

Laravel

No Laravel, prefira $request->validate() e paginate() (o x-lista já lê o formato). Consulta continua útil para a lista branca de ordenação: $c = Consulta::ler($request->query(), [...]); $query->orderBy($c->coluna(), $c->direcao())->paginate($c->porPagina()).

Csv (exportação)

@@@php use AlpineForm\Helpers\{Consulta, Csv}; $c = Consulta::ler($_GET, ['ordenaveis' => ['nome' => 'c.nome'], 'ordem' => 'nome']); // filtros e ordem, sem paginação $st = $pdo->prepare("SELECT id, nome, email, saldo, criado_em FROM clientes c WHERE ... ORDER BY {$c->sqlOrdem('c.id')}"); $st->execute($params); Csv::enviar('clientes.csv', [ 'id' => 'Código', 'nome' => 'Nome', 'email' => 'E-mail', 'saldo' => 'Saldo', 'criado_em' => 'Cadastro', ], $st); @@@
MétodoFaz
Csv::enviar($nome, $colunas, $linhas, $opcoes)Cabeçalhos de download (text/csv; charset=utf-8, Content-Disposition com nome seguro, no-store, nosniff), escreve e encerra.
Csv::escrever($recurso, $colunas, $linhas, $opcoes)Escreve num recurso aberto (php://output, arquivo, php://temp); devolve a quantidade de linhas.
Csv::texto($colunas, $linhas, $opcoes)O CSV como texto (testes, anexo de e-mail, frameworks que esperam o corpo pronto).
Csv::linhasDoBanco($pdo, $sql, $params) · Csv::linhasPorLote($buscar, $tamanho)Leitura com memória constante (milhões de linhas).
Csv::comprimir($recurso)Grava em gzip (para gerar .csv.gz em arquivo, por exemplo num job).
Csv::nomeSeguro($nome)Nome de arquivo sem caminho, aspas nem acentos; garante extensão.
  • $colunas: ['chave' => 'Título'] (ordem e títulos do arquivo) ou lista de chaves. Chave ausente na linha vira célula vazia — colunas extras do SELECT não vazam para o arquivo.
  • $linhas: array, PDOStatement, gerador (yield) ou qualquer Traversable de arrays/objetos — escrito linha a linha, sem carregar a tabela na memória.
  • Padrões para o Excel em português: separador ;, BOM UTF-8 (acentos corretos), quebra \r\n, aspas conforme RFC 4180. Opções: separador, bom, cabecalho, protegerFormulas.
  • Injeção de fórmulas: célula que começa com =, +, -, @, tab ou CR recebe um apóstrofo na frente ('=HYPERLINK(...)), para o Excel não executar o que alguém digitou num cadastro. Números como -10.5 ficam intactos.
  • null vira vazio, true/false viram 1/0, datas (DateTimeInterface) viram Y-m-d H:i:s.

Milhões de linhas

@@@php // MySQL/MariaDB e SQLite: lê sem carregar o resultado inteiro (o PDO do MySQL, por padrão, carrega tudo) $linhas = Csv::linhasDoBanco($pdo, 'SELECT id, nome, email FROM clientes WHERE uf = ? ORDER BY id', [$uf]); // PostgreSQL, SQL Server, Oracle, Eloquent, APIs: em lotes, por chave (memória constante) $linhas = Csv::linhasPorLote(function ($ultima, $tamanho) use ($pdo, $uf) { $st = $pdo->prepare('SELECT id, nome, email FROM clientes WHERE uf = ? AND id > ? ORDER BY id LIMIT ' . (int) $tamanho); $st->execute([$uf, $ultima ? $ultima['id'] : 0]); return $st->fetchAll(PDO::FETCH_ASSOC); }, 5000); Csv::enviar('clientes.csv', ['id' => 'Código', 'nome' => 'Nome', 'email' => 'E-mail'], $linhas, [ 'gzip' => true, // comprime em fluxo se o navegador aceitar (5–6x menos tráfego); ele salva o .csv normal 'tempoLimite' => 600, // set_time_limit // 'maxLinhas' => Csv::LIMITE_EXCEL, // corta em 1.048.575 linhas para abrir inteiro no Excel ]); @@@
Opção de enviar()PadrãoEfeito
descartarBuffertrueDescarta buffers de saída ativos (ob_start do Joomla e de frameworks), que guardariam o arquivo inteiro na memória — e qualquer saída anterior que corromperia o CSV.
gzipfalseContent-Encoding: gzip em fluxo quando o navegador aceita e o PHP não comprime sozinho (zlib.output_compression).
tempoLimitenullSegundos para set_time_limit (0 = sem limite).
maxLinhasnullPara de escrever depois de N linhas (também em escrever()).
  • As linhas são acumuladas em blocos de 64 KB antes de gravar (uma escrita por linha deixava 2 milhões de linhas 4x mais lentas) e enviadas ao cliente bloco a bloco; o cabeçalho X-Accel-Buffering: no evita que o nginx segure a resposta.
  • Com linhasDoBanco() no MySQL, a conexão fica ocupada até o fim da leitura: não execute outra consulta nela no meio da exportação (abra outra conexão se precisar).
  • Proxies e balanceadores costumam cortar conexões sem dados por 60 s: garanta índice para o ORDER BY, para a primeira linha sair logo. Se a consulta for lenta por natureza, use exportação em segundo plano.
  • Teste de carga: npm run test:php:carga (gera 2 milhões de linhas; usa o MySQL local se houver — AF_MYSQL_DSN, AF_MYSQL_USUARIO, AF_MYSQL_SENHA).

CSRF (PHP puro)

@@@php // no layout (a sessão é iniciada se ainda não estiver) // no endpoint if (!Csrf::valido()) { Resposta::enviar(Resposta::erro('Sessão expirada. Recarregue a página.', 419)); } @@@

O AlpineForm envia o token no cabeçalho X-CSRF-TOKEN (só para a mesma origem). Csrf::valido() também aceita o campo _token, para formulários que funcionam sem JavaScript. A comparação usa hash_equals.

Compatibilidade e testes

  • PHP 7.0 a 8.5, sem extensões obrigatórias (usa mbstring quando existe). Sem declare(strict_types), para conviver com código legado.
  • Testes: php php/tests/run.php (também em npm run test:php), executados em PHP 7.1, 7.4, 8.4 e 8.5.
